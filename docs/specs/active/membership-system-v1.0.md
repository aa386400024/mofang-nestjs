# 会员体系设计方案 v1.0

> **路径**：`docs/specs/active/membership-system-v1.0.md`
> **状态**：待用户确认
> **创建日期**：2026-11-07
> **关联 WP**：WP27（支付）、WP33（会员分层 TTS）、WP39（emotion 映射）、WP40（语气词标签）

---

## 一、概述

### 1.1 背景

心塑 App 进入商业化阶段，需要一套企业级会员体系支撑订阅收入。当前后端已有 `free / plus / pro` 的雏形（`src/profile/dto/membership.dto.ts`），但缺少完整的配额、价格、活动、权限设计。

### 1.2 目标

- 四档会员体系（Free / Plus / Pro / Max）
- 语音对练时长按月配额，文字功能全开放
- 价格和时长全部后台可配置，运营不用发版
- 三层兜底控制成本，防止超预算
- 活动系统用 flex-rules-engine，规则可配置

### 1.3 范围

本方案覆盖：
- 会员等级与配额模型
- 价格配置与活动系统
- 督导权限分层
- TTS 质量分层
- 工程数据模型

本方案不覆盖：
- 具体支付接口对接（WP27）
- 前端页面设计
- B 端机构版（远期）
- 真人督导服务（单独付费）

## 二、等级定位

### 2.1 四档会员

| 等级 | 定位 | 目标用户 | 月费（参考） |
|---|---|---|---|

> 注：价格只是参考，实际以后台配置为准。

## 三、时长配额模型

### 3.1 核心原则

- **语音对练时长按会员周期配额**，文字功能全开放
- **不结转**：没用完的时长过期清零，不累计到下个周期
- **按会员周期刷新**：每个会员周期开始时重置当月时长（不是自然月，是按用户开通日算的周期）

### 3.2 各等级配额

| 等级 | 月度语音时长 | 免费体验时长 | 加包规格 |
|---|---|---|---|
| Free | 30 分钟/月（按月刷新） | 25 分钟（一次性，新用户注册送） | - |
| Plus | 300 分钟/月 | - | 100 分钟 / 20 元 |
| Pro | 800 分钟/月 | - | 100 分钟 / 15 元 |
| Max | 2000 分钟/月 | - | 100 分钟 / 10 元 |

> 注：所有数值后台可配置，运营随时可以调。

### 3.3 时长调整生效时机

运营在后台改时长时，手动选择生效时机：

| 选项 | 说明 |
|---|---|
| 立即生效 | 当前周期剩余时长按新配额算（补差额：新配额 - 已用） |
| 下个周期生效 | 当前周期不变，下个会员周期开始时按新配额算 |

**示例（立即生效）：**
- 原来 Plus 300 分钟，用户已用 200 分钟，还剩 100 分钟
- 运营改成 500 分钟，选"立即生效"
- 用户现在有：500 - 200 = 300 分钟

## 四、价格配置系统

### 4.1 价格模型

每个等级有两个价格字段：

| 字段 | 说明 | 示例 |
|---|---|---|
| `list_price` | 原价（日常挂牌价） | Plus 49 元/月 |
| `promo_price` | 活动价（活动期间生效） | Plus 39 元/月 |

活动价带：
- `starts_at` / `ends_at`：活动时间窗
- `name` / `description`：活动名称和说明

### 4.2 三层兜底

#### 第一层：活动总预算上限

| 规则 | 说明 |
|---|---|
| 每个活动有总预算 | 比如"双十一特惠"，总预算 5000 元 |
| 每发一个奖励扣预算 | 一个用户优惠 10 元，就扣 10 元预算 |
| 预算用完活动自动结束 | 到 0 就下架，恢复原价 |
| 后台能看消耗 | 已用多少、还剩多少、多少人参加、转化率 |

#### 第二层：单个用户优惠上限

| 规则 | 说明 |
|---|---|
| 每个用户累计优惠有上限 | 比如累计最多优惠 100 元 |
| 超过就按原价 | 再参加活动也不优惠了 |
| 作用 | 防羊毛党刷活动 |

#### 第三层：成本兜底（最后一道防线）

| 规则 | 说明 |
|---|---|
| 每日 TTS 总成本上限 | 比如每天最多花 500 元 |
| 超了自动降级 | hd → turbo，成本降一半 |
| 超了自动限流 | 实在不行就排队，新用户先等 |
| 作用 | 前面两层都没拦住，这层兜底 |

### 4.3 付款周期

| 周期 | 价格 | 说明 |
|---|---|---|
| 月付 | 原价 × 1 | 按月扣款 |
| 季付 | 原价 × 3 | 按季度扣款 |
| 年付 | 原价 × 12 | 按年扣款 |

**赠送方式（运营后台自由选，大厂标准）：**

| 赠送类型 | 说明 | 示例 | 周期结束时清零吗？ |
|---|---|---|---|
| 送会员延长 | 会员周期延长 | 季付送 1 个月 = 会员多 1 个月 | - |
| 送练习时长 | 额外加练习分钟数（记到 bonusMinutes） | 季付送 300 分钟练习时长 | 不清零，永久有效 |

> 注：送多少、送哪种，全部后台可配置，运营随时可以调。赠送的练习时长是永久有效的，不随会员周期清零。

### 4.4 取消订阅与自动续费（大厂标准）

**取消后行为：**
- 取消订阅后，当前周期内仍然可以使用会员功能
- 到期后自动降级为 Free，不会自动扣款
- 用户可以随时重新开通

**扣款失败处理（大厂标准）：**
- 扣款失败后，自动重试 3 次（间隔 1 天、3 天、7 天）
- 重试期间会员功能仍然可用
- 3 次都失败后，暂停会员功能，用户手动付款后恢复
- 暂停期间时长冻结，恢复后继续用（不是照常消耗）
- 不会直接降级，给用户缓冲时间

**升级/降级 prorate（大厂标准）：**
- 升级（Plus → Pro）：补差价 = (Pro 价格 - Plus 价格) × (剩余天数 / 总天数)
- 降级（Pro → Plus）：当前周期结束后生效，不退差价

### 4.5 跨平台渠道（iOS vs 安卓）

**原则：** 价格和时长两边完全一样，用户体验一致。

**成本承担：** 苹果抽成 30% 我们自己承担，当作用户获取成本，不通过价格或时长转嫁给用户。等用户规模起来了，再慢慢调整定价策略。

> 注：所有数值后台可配置，后续可以根据实际成本和利润情况调整。

### 4.6 退款政策（企业级）

**退款原则（大厂标准）：**
- 未使用：7 天无理由全额退款
- 已使用：按剩余天数比例退款（不扣时长成本，时长是会员权益的一部分）
- 恶意退款（刷完时长再退款）：拒绝，人工审核

**具体规则：**

| 场景 | 处理方式 |
|---|---|
| 7 天内未使用（天数未消耗） | 全额退款 |
| 7 天内已使用部分天数 | 按剩余天数比例退款（比如用了 3 天，退 27/30 的钱，不扣时长成本） |
| 超过 7 天 | 不退款（但可以取消自动续费） |
| 恶意退款（短时间内大量使用时长后申请退款） | 拒绝，人工审核 |

## 五、督导权限分层

| 功能 | Free | Plus | Pro | Max |
|---|---|---|---|---|
| AI 自动快评（技术 9 项 + BDI 变化） | ✅ | ✅ | ✅ | ✅ |
| 成长档案总览（雷达图 + 趋势） | ❌ | ✅ | ✅ | ✅ |
| 多流派对比评分 | ❌ | ❌ | ✅（默认 CBT + 人本，后台可配） | ✅（全部 4 个流派） |
| 深度月度复盘报告 | ❌ | ❌ | ✅ | ✅ |
| 来访角色池 | ❌ | ✅（基础池） | ✅（全部池） | ✅（全部池） |
| 优先体验新功能 | ❌ | ❌ | ✅ | ✅ |
| 真人督导批注 | ❌ | ❌ | ❌ | ✅（每月 2 次，后期支持） |
| 专属客服 / 优先支持 | ❌ | ❌ | ❌ | ✅ |
| 数据导出 / 高级分析 | ❌ | ❌ | ❌ | ✅ |

### 设计理由

- **基础快评免费用户也有**：快评是即时反馈，是对练的"完成感"来源；免费用户对完练什么反馈都没有，留存会崩。快评成本低（毫秒级、零 LLM，WP43 已做）。
- **成长档案要会员才有**：成长档案是"长期价值"的体现，是付费转化的钩子。免费用户对 1-2 场就够了，不需要看趋势。
- **多流派对比 Pro 才有**：这是高频使用者的差异化需求，新手不需要流派差异。Pro 开放 2 个流派，Max 开放全部 4 个。
- **真人督导 Max 才有**：真人督导是高成本服务，包含在 Max 套餐里（每月 2 次），单独付费的话更贵。

## 六、TTS 质量分层

| 等级 | TTS 模型 | emotion 映射（WP39） | 语气词标签（WP40） |
|---|---|---|---|
| Free | Speech-2.8-turbo | ✅ | ✅ |
| Plus | Speech-2.8-turbo | ✅ | ✅ |
| Pro | Speech-2.8-hd | ✅ | ✅ |
| Max | Speech-2.8-hd | ✅ | ✅ |

### 设计理由

- **emotion 和语气词标签是基础能力**：真实性是底线，不能因为等级低就牺牲。
- **只有模型本身有差异**：hd 模型更自然、更细腻，turbo 模型成本更低。
- **对我们没啥损失**：emotion 和语气词标签是 prompt 里加的，不增加 TTS 成本。

## 七、活动系统（flex-rules-engine）

### 7.1 活动模型

活动就是"**条件 → 动作**"的规则：

```
条件：用户做了什么？
动作：给什么奖励？
```

用 flex-rules-engine 实现，规则存在 DB 里，运营在后台配，不用写代码。

### 7.2 奖励分级

| 级别 | 示例 | 叠加规则 |
|---|---|---|
| **低价值** | 送 10 分钟时长、送 1 天 Plus 体验 | 随便叠加，没限制 |
| **中价值** | 送 30 分钟时长、送 3 天 Plus 体验 | 每日最多叠 2 个 |
| **高价值** | 送 100 分钟加包、送 7 天 Pro 体验 | 互斥，只能选一个 |

### 7.3 每日上限

- 每天最多送 50 分钟免费时长（防止刷）
- 每天最多送 3 天会员体验（防止刷）

### 7.4 规则示例

| 条件（触发事件） | 动作（奖励） | 级别 |
|---|---|---|
| 拉新 1 人成功注册 | 送 30 分钟时长 | 中价值 |
| 连续登录 7 天 | 送 3 天 Plus 体验 | 中价值 |
| 完成 10 场对练 | 送 1 次加包（100 分钟） | 高价值 |
| 邀请好友付费成功 | 送 7 天 Pro 体验 | 高价值 |

**会员体验到期后降级规则（大厂标准）：**
- 会员体验到期后，降级回**原来的等级**，不是降级回 Free
- 比如：用户原来是 Plus，参加活动送 7 天 Pro 体验。7 天后到期，降级回 Plus，不是降级回 Free

## 八、工程模型

### 8.1 数据模型

#### membership 表

```typescript
{
  userId: string;
  tier: 'free' | 'plus' | 'pro' | 'max';
  status: 'active' | 'expired' | 'trial' | 'cancelled';
  startsAt: Date;
  expiresAt: Date;
  
  // 时长配额
  monthlyMinutes: number;      // 月度总时长（从 tier 配置来，按会员周期刷新）
  usedMinutes: number;          // 本周期已用时长
  bonusMinutes: number;         // 赠送时长（活动送的，永久有效，不随周期清零）
  resetAt: Date;               // 下次重置时间（下个会员周期开始时）
  
  // 优惠记录
  totalDiscount: number;        // 累计优惠金额（元）
  monthlyDiscount: number;      // 本月优惠金额（元）
  
  // 支付信息
  orderId: string;             // 关联订单
  autoRenew: boolean;          // 自动续费
}
```

#### tier_config 表（后台配置）

```typescript
{
  tier: 'free' | 'plus' | 'pro' | 'max';
  listPrice: number;            // 原价（元/月）
  promoPrice: number;           // 活动价（元/月）
  promoStartsAt: Date | null;   // 活动开始时间
  promoEndsAt: Date | null;     // 活动结束时间
  monthlyMinutes: number;        // 月度时长配额
  freeTrialMinutes: number;     // 新用户体验时长
  ttsModel: string;             // TTS 模型
  hasEmotion: boolean;          // emotion 映射开关
  hasTags: boolean;             // 语气词标签开关
  // ... 其他权限开关
}
```

#### activity_rule 表（活动规则）

```typescript
{
  id: string;
  name: string;                 // 活动名称
  condition: object;            // 条件（flex-rules-engine 格式）
  reward: object;               // 动作（奖励）
  level: 'low' | 'medium' | 'high';  // 奖励级别
  startsAt: Date;               // 生效开始时间
  endsAt: Date;                 // 生效结束时间
  budget: number;               // 总预算（元）
  spent: number;                // 已花费预算（元）
  maxDiscountPerUser: number;   // 单个用户优惠上限（元）
}
```

### 8.2 时长扣减策略

**会话开始时预扣 + 结束时实扣：**

- **开始时**：检查剩余时长 ≥ 10 分钟，预扣 10 分钟
- **结束时**：计算实际时长，多退少补
- **中途断了**（崩溃 / 网络问题）：按已记录的时长实扣，不按预扣

**为什么要预扣？**
- 防止用户开了会话就跑，白嫖 TTS 成本
- 预扣 10 分钟是合理的，一场对练通常 20-40 分钟

### 8.3 并发控制

- 同一个用户同时只能开 1 个语音会话
- 后端在会话开始时检查：有没有 active 的会话？有就拒
- 防止用户开两个会话同时刷时长
