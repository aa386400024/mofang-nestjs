### 洞 2：督导分析链路还是 mock

- `src/counselor/providers/supervision.service.ts:123` `generateFeedback`
  → `:135` 调 `:274` `mockGenerateFeedback`（静态 prompt + 规则 + 伪随机分数），**0 LLM 调用**。
- 文件头注释自认：「V0.5 mock 阶段: 只生成 prompt 字符串 + mock 评分, **V1.x 真接 LLM 时改 provider 注入**」。

### 洞 3：真 LLM 管道在「另一个宇宙」，且不认 counselor 的数据

**好消息**：`src/agent/supervisor/supervisor.service.ts:65` `runReport` 已经是完整真接实现——
transcript → prompt → `LlmService.streamChat` → 收集 rawText → `JSON.parse` → 字段校验
→ 失败落 `parse_error` + 存原文（`:151` `parseAndValidate`）。
这套「流式收字 + JSON.parse + 校验 + 兜底」的骨架就是 VS-A 要复制的模板。

**问题**：

1. 它吃 `src/agent/supervisor/supervisor.types.ts` 的形状，落 supervisor 自己的表，
   **跟 counselor 的 `supervision_feedback`（4 字段 payload）和 `training_sessions.transcript` 两边都不通**。
2. visitor 侧同理：`src/agent/visitor/visitor.prompts.ts` `renderSystemPrompt` 只认
   `complaint / personality / background` + difficulty + emotion，
   **完全不知道** counselor 的 `training_sessions.persona*` 5 字段、不知情同意阶段、
   不知信任度、不知已解锁档案、不知作业反馈与咨询师笔记。
3. `LlmService`（`src/agent/llm/llm.service.ts`）**只有 `streamChat`**，无非流式 / 无 JSON mode；
   MiniMax 请求体（`MiniMaxChatRequest`）固定 `stream: true`，无 `response_format`。
   结构化输出目前只能走「收流 + prompt 要求纯 JSON + JSON.parse」（supervisor 已在用这招）。

→ **根因判断：缺的是「会话上下文装配层」。**
M1（人设）/ M2（知情同意）/ M3（轻提示 + techStats）/ M4（作业反馈 + 笔记）各自去改 visitor prompt，
会长出 4 份重复的拼装代码。**必须有且只有 1 处知道「一个会话的上下文怎么拼」**。

## 7. 落地基线事实（代码核查回传，VS-A 动手前必读）

> 只读核查结论，证据路径:行号见 `docs/progress/v1.2-landing-plan-2026-10-21.md` 上下文。**5 个最容易踩的坑**：

### 坑 1：migration 注册点不是 `src/migration/index.ts`

- `src/migration/index.ts` **不被任何代码 import**（全仓 grep 0 命中），只是镜像/文档。
- **真正生效点**：`bin/ormconfig.ts` — 顶部 `import` + `migrations: [...]` 显式数组。
- 漏登记的现象极具迷惑性：`migration:run` 输出 **"No migrations are pending"**（看着像都跑完了），
  实际是压根没被看见 → 表不建 → 运行时 500。`bin/ormconfig.ts:107-111` 有团队自己写的踩坑记录。
- **下一个 counselor 系时间戳 = `1714900000013`**（沿用 17149 族；`1714900000005` 是历史空号）。
- **`migration:generate` 检测不到 counselor entity**（`bin/ormconfig.ts:140` 的 entities glob 只覆盖 `src/entity/**` 的 sampledb）→ counselor 系 DDL **一律手写**。
- 手写 DDL 模板见 `src/migration/1714900000009-AddTrainingSessions.ts:48-90`：
  `CREATE TABLE IF NOT EXISTS` + `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`
  + `DATETIME(6)` + 表内 `INDEX idx_xxx (...)` + down 段 `DROP TABLE IF EXISTS`。

### 坑 2：两个类名都叫 `LlmModule`

- 栈 A `src/agent/llm/llm.module.ts` → `LlmService`（MiniMax 流式，含 `streamChat` / temperature / 自定义 system prompt / 自动重试）
- 栈 B `src/llm/llm.module.ts` → `LlmRouterService`（多厂商路由，含**非流式** `chat()` / `embed()` / tier 模型映射）
- 栈 B 需要 `LLM_<PROVIDER>_API_KEY`，`.env` 里**一个都没有** → 现在启动就是 `(none)`。
- **VS-A 选栈 A**（`.env` 已有 `MINIMAX_API_KEY` / `MINIMAX_BASE_URL` / `MINIMAX_LLM_MODEL`，且已被 `supervisor.service.ts` 端到端跑通）。
- import 用别名（同 `src/knowledge-base/knowledge-base.module.ts:21` 先例）：
  `import { LlmModule as AgentLlmModule } from '../agent/llm/llm.module';`

### 坑 3：结构化 JSON 没有 provider 级支持

全仓 grep `response_format|json_object|json_schema` **只命中 1 条 TODO 注释**。
既有范式（`src/agent/supervisor/supervisor.service.ts:102-175`）就是 VS-A 要抄的：
`prompt 写死 schema → 流累加 rawText → JSON.parse → 手写 shape 校验 → 失败落 parse_error 不抛`。
`SUPERVISOR_TEMPERATURE = 0.3` / `SUPERVISOR_MAX_TOKENS = 2500`（`:41-43`）是现成的保守取值参考。

### 坑 4：counselor 系软删不是 `@DeleteDateColumn`

10 个 counselor entity 全部用普通 `@Column({ type: 'datetime', name: 'deleted_at', nullable: true })`
（`@DeleteDateColumn` 只在 `src/user/entities/user.entity.ts:105` 等处）→ **不会自动过滤**，
每处查询必须手写 `deletedAt: IsNull()`（实证 `src/counselor/providers/supervision.service.ts:86`）。

### 坑 5：worker 队列已有 supervisor，但没有 counselor/作业队列

- BullMQ **不用 `@nestjs/bull`**，直接用原生 `Queue` + `Worker`；接入在 `onModuleInit` 建、`onModuleDestroy` 关。
- 统一约定：`prefix: 'bullmq'`、`defaultJobOptions { attempts: 3, backoff: exponential/1000,
  removeOnComplete {count:1000, age:86400}, removeOnFail {count:5000} }`、
  `enqueue(): boolean` **失败不抛** → 调用方 `processSync` 兜底。
- 现有队列：`audit-log` / `supervisor`（`QUEUE_NAMES`，`src/shared/infra/redis/redis.constants.ts:55-61`）
  / `kb-scheduled-publish`；`email-outbox` / `sms-outbox` 是占位无实现。
- **homework 队列全仓不存在** → v1.2 §7.2 需在 `QUEUE_NAMES` 新增一条。
- 延迟任务范例：`src/knowledge-base/providers/scheduled-publish.service.ts:66-79`
  （`delay: Math.max(0, target - Date.now())` + `jobId` 幂等）。
  注意 `backoff.delay`（重试退避）与 `delay`（延迟执行）是两回事。

### 新增文件必须带的格式

- 每个新 `.ts` 文件头带 **5 段治本注释**（原因 / 修法 / 反双胞胎 / 验证 / 时间戳），见 `code-fix-five-segment-comment` skill。
