## 1. 5 个治本点

### VS-1: 训练题内容从应用代码迁出到 DB (knowledge base 接入点)
- **新写**: `src/counselor/config/training-exercise-seeds.ts` (内容数据, 400 行), `src/counselor/seeds/training-exercises.seed.ts` (幂等 upsert 逻辑), `bin/seed-training-exercises.ts` (独立执行入口), `tsconfig.scripts.json` (运维脚本专用 tsconfig)
- **关键设计**:
  - 训练题用稳定 ID `ts_emotion_reflection / ts_fact_feeling_separation / ... / ts_ice_breaking` (10 个), 知识库接入时按此 ID 建映射做幂等同步, **改名等同换一道题 (会丢历史答题记录)**
  - 移出应用启动流程 (原 `onModuleInit` 灌数据), 内容与应用二进制解耦 —— 改文案不需要重启 + 重新灌
  - 实体列存 JSON 时键序被规范化 (MySQL JSON 按「键长度→字节序」排序), `hasDrift` 用键序无关深比较, 避免永远 `更新 10` 的假信号
  - 实体列 `tinyint` 存布尔 (0/1), `sameBoolean()` 归一比较, 避免类型不一致永远漂移
  - 知识库接入路径: 同一张 `training_exercises` 表, 知识库同步任务按稳定 ID upsert, **本 seed 可下线**
- **反双胞胎**: 不用 migration 灌内容 (改文案每次都加 migration, 迁移历史被业务内容淹没); 启动期不自动跑 seed (多副本并发写 + DB 不可达会阻塞启动)
- **执行入口**: `npm run seed:training`, 连跑两次应 `未变 10`

### VS-2: 进度聚合端点 (单请求零 N+1)
- **新写**: `src/counselor/providers/training-exercise.service.ts` (~360 行, 含幂等 seed 删除后的清理版), `src/counselor/dto/training-exercise.dto.ts`
- **关键设计**:
  - `GET /counselor/training-exercises/progress` 一次返回 `summary + items[]` (10 项固定), 禁止 N 次 per-mode 请求 (设计规格 §10 性能预算)
  - `submitAttempt` 服务端确定性评分 (命中 90 / 未命中 45), **零随机** —— 客户端 mock 的 `math.Random()` 随机分让用户无法复盘, 必须根治
  - 维度分按 `rubric.dimensions` 派生 (命中 100 / 未命中 35), 跟服务端约定 1:1
  - 答题反馈 `improvementHints` 数组 (未命中时非空) 改进提示, 客户端反向解析以避免改 entity 契约
- **反双胞胎**: 不在客户端算分数 (两端不一致); 不返回 `correctOptionIndex` 到列表接口 (答案泄漏)

### VS-3: 偏好持久化 + Hero 显示开关
- **新写**: `src/counselor/enums/counselor-ui-preference-key.enum.ts`, `src/counselor/entities/counselor-ui-preference.entity.ts`, `src/counselor/providers/counselor-ui-preference.service.ts`, `src/counselor/controllers/counselor-ui-preference.controller.ts`, `src/migration/1714900000012-AddCounselorUiPreferences.ts`
- **关键设计**:
  - 白名单 key + 默认值 (`COUNSELOR_UI_PREFERENCE_DEFAULTS`), 未知 key 抛 400, 防止 typo 写入脏偏好
  - 读失败降级默认 (`显示 Hero`), 写失败返回 false 让 UI 明确提示而非静默假成功
  - 不打密码 (响应输出只回显 host/port/database 等定位信息)
  - 用户拍板「右上角 OR 我的 tab 二选一」, 后端方案独立支持两处入口
- **反双胞胎**: 不在 entity 用裸 string key (拼写无保护); 不把隐私/安全设置混入本表

### VS-4: 路由意图显式化 (消除 id 字符串猜路由)
- **改**: `src/counselor/dto/counselor-home.dto.ts` (+`target` enum)、`src/counselor/providers/counselor-home.service.ts` (skill 分类收敛为单入口)
- **关键设计**:
  - 后端在 DTO 显式下发 `target: 'specializedSkills' | 'visitorPreset' | 'scriptWorkshop' | 'examLibrary'`, 客户端**只做单一 switch 分派**
  - 客户端原用 `scenario.id.startsWith('skill_')` / `id === 'script_polish'` 字符串前缀猜路由 —— 后端改名/新增 id 客户端静默走错分支, 编译期与测试都无法发现
  - 训 tab 「专项技能」分类收敛为单入口大卡 (collapsed: true, scenarios: [], target: 'specializedSkills'), 语义统一指向详情页的 10 个训练项 (消除「训 tab 说 3 项, 进去看到 10 项」的认知冲突)
- **注意**: 实际客户端实现时发现 `SpecializedSkillsDetailRoute` 与 `ScriptWorkshopRoute` 在 `router.gr.dart` 中**不存在** (auto_route 没生成) —— 这正是路由键被隐藏时的副作用, 训练营生期就改成显式目标 + 详情页走 `MaterialPageRoute + BlocProvider` 注入
- **反双胞胎**: 不保留客户端 id → 路由映射表 (会再次 drift); 不保留 3 段 Tab/sceneTab (那才是冗余本身)

### VS-5: 全程静态验证链 (治本治到 0 错而非压错)
- **新写**: 多次 tsc 是 `EXIT=2` → `EXIT=0` 的迭代, 12 处真编译错一次性根除:
  - `TS2353 × 10`: `interface TrainingExerciseSeed extends TrainingExerciseRubric` 把 rubric 字段摊平到了 seed 顶层, 与实体嵌套结构冲突 → 改为 `rubric: TrainingExerciseRubric` 声明属性
  - `TS2322 × 3`: 本项目 `@nestjs/swagger` 版本 `SchemaObject.type` 不收字符串 `'object'`, 改用 `Object` 构造函数; `where: { deletedAt: null }` 中 `deletedAt` 是 Date 列不接受 null, 改用 `IsNull()` (后者是关键 —— `as any` 强转会让运行时静默失效, 软删记录漏进查询)
  - `TS6133 × 2`: 未使用的 `IsString` import 移除
  - `TS4111 + TS5012`: 项目私有的 process.env.X 点访问全局 lint 不收, **不修** (110 处跨 14 文件, 属独立整改 scope); 用 `ts-node -T -P tsconfig.scripts.json` transpile-only 跳过 (scripts 本就不在 build 检查范围)
  - `Record<string, unknown>` 中转把 db 类型信息洗掉 → 改为 `as { db: DbConfig }` 一次性 cast
  - `${候}` 占位符在 JS 模板串里被误插值 → 在 console.log 单引号里改字符串拼接
  - `package.json` 写 `//` 注释 → JSON 不支持, 整个 `npm run` 瘫痪; 已记入 USER.md
- **反双胞胎**: 不在 scripts/ 单文件层治标 (`-P tsconfig.build.json`), 因 build 配置 exclude 了 `bin/**` —— 治本: 独立 `tsconfig.scripts.json` 设 `rootDir: '.'`, 语义清晰零副作用
