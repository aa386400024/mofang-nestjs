## 0. 一句话

**AI 来访者不再是"通用 persona 随机反应"，而是被咨询师配置好的那个来访者在演。**
全量人设（7 大块）→ agent 侧 system prompt；信任度决定它**说多少**；每轮来访的披露被抽取成动态解锁档案，并**按披露深度加权推进信任度** → 下一轮它说得更多。

| 拍板项 | 结论 | 落地方式 |
|--------|------|---------|
| ① 接线方案 | **B. 依赖倒置 + provider token** | agent 侧新增 `VisitorContextRegistry`（@Global）+ `VisitorContextContributor` 插槽；counselor 侧实现 `CounselorVisitorContextContributor` 并在 `onModuleInit` 注册。**agent 侧 0 处 import counselor** |

## 3. 8 条实现决策（spec ↔ 代码差异）

| # | spec 原文 | 落地做法 | 原因 |
|---|-----------|---------|------|
| **D17** | §4.3「长程：注入 VisitorFullPersona 全量 + 当前信任度 + 已解锁 CaseProfileEntry 列表」 | **依赖倒置 + @Global 注册表**（agent 只提供插槽，不认识业务） | 方案 A（agent 直连 counselor 数据）破坏单向依赖；**方案 B 的 provider token 直注也会循环依赖**（counselor→agent 取 LlmModule，agent→counselor 就成环）。@Global 注册表是唯一能双向可见又不循环的做法 |
| **D18** | §4.3 未说明「AI 来访者怎么知道这是哪个来访者」 | **sessionId 绑定契约**：训练/长程会谈的 voice WS sid = counselor 的 sessionId，贡献者按 id 反查 | 语音链路（ASR/TTS/visitor）保持通用不重造；业务设定由业务侧注入。前端只改 1 处（连 WS 用 counselor 的 sessionId） |
| **D19** | §6.1「off：完全无提示，结束后统一出报告」 | **修订 D9**：分析**始终跑**，档位只控「hint 是否落库 + 推送」 | 原 D9 定的"off 时不采集"会致命：档案永远不填 → 信任度永远不涨 → 信息暴露节奏永远停在第一档 → **整个 M1 机制失效**。而关掉提示的恰恰是做长程个案的进阶用户 |
| **D20** | §6.1 轻提示 + §6.4 移情标记 + §4.2 档案抽取是三段需求 | **1 次 LLM 出 3 段**（hint + mark + disclosures） | 三者读同一段对话、发生在同一时刻。分开判定会自相矛盾（同一条回复，判提示说"没接住情绪"、判标记说"来访很平静"、判披露说"来访讲了自己的名字"——第三种解读必然跟第二种冲突） |
| **D21** | §4.1「按咨访信任度 (0.0-1.0) 分级」但没说「披露了什么加多少信任」 | 按**锚点所在人设块分档加权**（浅层事实 +0.03 / 关系与内在 +0.06 / 深层 +0.08），**服务端规则**可复算可解释；重复披露同一锚点**不重复加**（只更新内容） | 一刀切 +0.05 会让"披露童年被打"跟"说了自己叫张伟"一样重，跟临床现实不符。权重若由 LLM 给 → 不可校准 + 两次判定不同 + UI 无法解释 |
| **D22** | §4.2「AI 每轮回复后抽取披露信息」 | 披露的 `anchorKey` **白名单**（7 大块前缀） | 锚点要能定位到人设图谱的真实节点，否则档案条目无法关联回人设、信任度权重也算不准。非法锚点整份判非法（宁可报错也不要写脏档案） |
| **D23** | §4.1「AI 底层全量人设（AI 独享）」+「信息暴露节奏按信任度分级」 | **AI 全量知情 + 规则约束它说不说**（不按信任度裁剪喂给 AI 的人设内容） | 若按信任度裁剪人设内容再给 AI，它就"不知道自己有什么"，被问到童年时只能编。真实咨询里来访者**知道**自己的创伤，只是还没准备好说 |
| **D24** | §4.1 信任度阈值 0.3 / 0.6 / 0.8 | 暴露规则写成**4 条人话 + 当前档位**（不让模型自己换算区间） | 模型对"0.3 ≤ 信任度 < 0.6"这种区间判断不稳定；写成"可以谈关系/可以谈情绪"这种可执行描述才稳 |

## 4. 关键约束（防"看起来能跑、实际破防"）

| 约束 | 实现方式 |
|------|---------|
| **agent 不认识业务** | `VisitorContextContributor` 插槽；agent 侧 0 处 import counselor |
| **两个画像不并存** | 业务块带 `replacesPersona` → 通用画像段被**替换**（不是追加）。两套画像并存会让模型选择性忽略，行为不可预期 |
| **不换 prompt**（信任度连续变化） | 上下文块每轮重算，system prompt 结构不变 → 跨轮人格连续（情绪状态/记忆都在 memory 里） |
| **单次训练也接得上** | 贡献者对单次训练产出**浅层版**行为块（身份/应对方式/难度），长程额外带全量人设 + 信任度 + 已解锁档案 |
| **AI 不能编造自己人设里没有的事实** | 行为块里显式写死这条硬约束 |
| **禁忌话题产生真实阻抗** | 行为块单列「禁忌话题」段，要求「被问到时回避/阻抗，不直接回答」 |
| **重复披露不刷信任度** | 同锚点只更新内容，不重复加权 |
| **档位只控展示** | tier=off → 不落库/不推 hint，但 mark 与披露照常产出（见 D19） |
| **上下文解析失败不影响会话** | registry 逐贡献者 try/catch，单个失败 → 降级为"无额外上下文" |

## 5. 端到端数据流

```
前端: POST /counselor/training-sessions            → 建会话 (拿 counselor 的 sessionId)
前端: WS /voice/training/<counselor的sessionId>    → 语音链路 (ASR/TTS/visitor)
        └─ VisitorService 每轮:
             └─ VisitorContextRegistry.resolve(sessionId)
                  └─ CounselorVisitorContextContributor.build()
                       └─ SessionContextBuilder.loadBySessionId()  ← 自动判定单次/长程
                            └─ 全量人设 + 信任度 + 已解锁档案
                       └─ buildVisitorPersonaBehaviorBlock()  ← 行为规则文本
                  └─ renderSystemPrompt(persona, memory, blocks)  ← 替换通用画像 + 覆盖难度/身份
             └─ LLM → 来访者按人设 + 信任度作答

前端: PATCH /counselor/training-sessions/:id/transcript  → 写入来访者那一轮
        └─ 入队 BullMQ (counselor-turn-analysis)
             └─ 1 次 LLM → { hint, mark, disclosures }
                  ├─ hint (tier=light) → live_supervision_hints → SSE live_hint
                  ├─ mark                → transference_resistance_marks → SSE transference_mark
                  └─ disclosures         → case_profile_entries (self_disclosed) → SSE profile_entry
                                          + 按披露深度加权推进 visitor_full_personas.trust_level
             └─ 下一轮 → 信任度已涨 → 来访者说得更多
```
