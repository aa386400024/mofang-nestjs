## 4. 关键边界与防呆

1. **`src/consent` vs M2 知情同意训练**：产品合规模块不动；M2 结果写 `training_sessions`，**绝不**写 `user_consent` 表。
2. **`long_term_cases.visitor_persona` vs `visitor_full_personas`**：浅表保留做 L1 冷启动；深表是长程专属，1:1 关联走应用层，不加 DB FK（跟现有 `caseId` pattern 一致）。
3. **7 维 raw vs 5 维收敛视图**：raw 表不动；5 维是 API 聚合产物，前端两个视图都保留。
4. **新表软删**：全部带 `deletedAt`（跟现有所有 entity 一致）。
5. **不走 `synchronize: true`**：跟 ADR-0003 一致，所有 schema 变更走 migration。
6. **不加 DB-level FK**：跟现有 `knowledge_chunks.itemId` / `long_term_case_sessions.caseId` pattern 一致，跨表引用走应用层校验（软删兼容）。

## 5. 已知遗留 / 下次接续入口

1. **V1.0 排期未拆周**：本 spec 只给了 V1.0/V2.0/V3.0 三档，未像 v1.1 §8 那样拆 W1-W12。等大炮确认 V1.0 范围后再排周。

3. **前端契约未对齐**：本 spec 是后端视角，前端 `xin_su_app` 需要单独对齐 DTO（尤其 `case_profile_entries` 的渲染时序、`live_supervision_hints` 的推送通道选 SSE 还是 WebSocket）。
4. **`counselor_ui_preferences` 新 key 待加**：实时提示档位 / 上帝视角开关 / 阶段性督导触发间隔（3/4/5 节）等偏好，下次扩白名单。
