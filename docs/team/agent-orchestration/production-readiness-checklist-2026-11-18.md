# 生产前收口 Checklist（Phase 2.5 → 生产）

> 单一入口：上线前五类工作（部署 / secrets / 数据库迁移 / 监控告警 / 回滚）必须逐项有 owner、有证据、有演练记录。
> 本文件是**清单**，不冒充演练结果；未勾选项不得声称「生产就绪」。

## 0. 放行门槛

| 项 | 口径 |
| --- | --- |
| 适用版本 | `integrate` 通过 13 项 required checks，且 Phase 2.5 出口条件完成书面判定 |
| 签字角色 | 技术负责人（大炮）+ 运维执行人 + 值班负责人 |
| 证据 | 每项附命令 / 截图 / 日志路径 / 时间戳；不接受「已配置」口头结论 |
| 冻结窗口 | 生产发布窗口内不打 tag、不改 master、不执行部署以外的写操作 |

## 1. 部署

- [ ] 产物来源固定：记录 `integrate` 完整 SHA 与构建产物哈希，禁止从工作树直接部署。
- [ ] 环境矩阵明确：开发 / 演练 / 生产三套配置分离，生产不得复用开发数据库或 Redis。
- [ ] 启动顺序：MySQL → Redis → 迁移 → 应用 → 健康检查；每步有超时与失败中止。
- [ ] 健康检查：`/health`（进程）与 `/health/ready`（依赖）分别验证，记录 HTTP 状态码与耗时。
- [ ] 配置注入：只从密钥管理/环境变量读取，不把密码、JWT secret 写进仓库或镜像。
- [ ] 发布记录：版本号、镜像/产物 hash、部署人、起止时间、变更摘要。

**放行证据**：一次演练环境的完整部署日志 + 一次生产窗口的发布单。

## 2. Secrets

- [ ] 清单化：数据库、Redis、JWT、第三方模型/短信/支付、GitHub token 逐项登记用途与 owner。
- [ ] 轮换：上线前对**曾出现在本机历史记录/日志**的密钥做一次轮换；轮换后旧值立即失效。
- [ ] 最小权限：CI 只用 `checks: read` / 必要写权限；生产密钥不下发到开发机。
- [ ] 存储：生产 secrets 只存于部署平台的密钥管理；本机 `.env` 仅演练，且不入库。
- [ ] 审计：记录谁在何时读取/轮换；离职或设备迁移后立即复核。

**放行证据**：secrets 清单 + 轮换记录 + 权限截图（脱敏）。

## 3. 数据库迁移

- [ ] 迁移清单：本次涉及的 migration 文件、执行顺序、预计耗时、锁表风险。
- [ ] 备份：生产迁移前做全量备份，记录备份路径与校验和；备份可恢复性抽验一次。
- [ ] 演练：在演练库按生产数据量级跑一遍，记录耗时与错误。
- [ ] 回滚：每个不可逆迁移必须有对应回滚脚本或补偿方案；无回滚方案不得上线。
- [ ] 双写/灰度：涉及字段改名的迁移按「扩展 → 双写 → 回填 → 切读 → 清理」分步，不一步到位。
- [ ] 校验：迁移后跑数据一致性检查（行数、关键枚举、外键、唯一约束）。

**放行证据**：迁移演练日志 + 备份校验和 + 回滚脚本路径。

## 4. 监控与告警

- [ ] 黄金指标：请求量、错误率、P95/P99 延迟、DB 连接池、Redis 命中率、队列积压。
- [ ] 业务指标：批次成功率、闸门失败率、回执摄入延迟、死信数、人工持单数。
- [ ] 告警阈值：错误率、P99、队列积压、磁盘、证书到期分别设阈值与持续时间，避免抖动误报。
- [ ] 告警路由：值班人 / 群 / 电话升级链明确；静默窗口与维护窗口有记录。
- [ ] 日志：结构化日志保留期、脱敏规则、检索入口；禁止记录完整对话与密钥。
- [ ] 仪表盘：上线前至少有一块可用的批次健康看板，不靠人肉查库。

**放行证据**：告警规则截图 + 一次人为触发告警的送达记录 + 看板链接。

## 5. 回滚

- [ ] 触发条件：错误率、核心接口不可用、数据不一致、批次大面积失败，量化到阈值。
- [ ] 回滚路径：应用回滚（上一版本产物）、配置回滚、数据库回滚（备份/补偿脚本）分别演练。
- [ ] 决策人：谁有权宣布回滚；回滚后谁负责复盘与恢复验证。
- [ ] 时限：从决定回滚到恢复服务的目标时间（建议 ≤ 30 分钟），演练中实测。
- [ ] 数据：回滚不得丢失已写入的合法业务数据；不可逆操作必须先导出。
- [ ] 复盘：回滚后 24 小时内出时间线、根因、改进项，进改进台账。

**放行证据**：一次完整回滚演练记录（含耗时、数据校验、复盘链接）。

## 6. 上线日 runbook

1. 冻结窗口开始，确认值班与回滚决策人在线。
2. 备份 + 迁移演练结果复核。
3. 部署新版本，跑健康检查与冒烟用例。
4. 观察 30 分钟黄金指标与业务指标。
5. 异常达阈值 → 按第 5 节回滚；正常 → 记录发布完成。
6. 24 小时内完成复盘与遗留登记。
