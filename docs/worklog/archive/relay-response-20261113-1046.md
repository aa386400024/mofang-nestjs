## 1. 三点待决策的第二意见

### (a) 分组回退顺序（角色 → 依恋风格组 → 全样本）与增量分位的样本量下限

**顺序本身合理，但必须补三件事，否则「回退」等于「静默换口径」：**

1. **每层必须记录「实际用上哪层」**（本单已实现：8 个角色全部命中角色级，回退链**未触发**）。没有这行，复核者无法区分「角色级结论」和「借了别组增量」——这正是台账线性表当年容易被误读的地方。
2. **样本量下限要硬性化且可配**：本单做成 `--min-samples`（默认 20），不足即标「样本不足 · 不出结论」。实测各角色级非退化差分样本 154~407，**全部在角色级**，回退链未触发，所以下限这次没起作用——但下限必须先存在，才能在下一个批次样本变小时拦住。
3. **建议再加一道「活跃轮占比」下限**：只看样本条数会被「零膨胀」骗过去——本单角色级活跃轮占比最低 **6.5%（亦舟）**，样本量 154~407 看着很足，但其中 88.5% 的差分是 0。建议 < 5% 直接判「增量估计不可用」。**实测最低 6.5% 只是勉强过线**，说明这道闸该加。

**另有一条反向建议**：回退链**不应跨角色借增量**。8 角色基线差 3~5 倍（safety 基线 0.10~0.40），跨组借增量会把「谁更容易到门槛」的信息抹平。回退到依恋风格组 / 全样本时，应该**降级为「仅标注来源」**（结论标「样本不足，结论仅供参考」），而不是给出一个看起来和角色级同权的单点轮次。

### (b) 外推 clamp 上下限

**已按内核真相源取，不自造规则**：`clamp01` → [0,1]（`src/engine-core/domain/emotion.ts`），`state-transition.ts:784-810` 的 `applyDeltaVector` 用它落 trust / safety / depth 三维。脚本不另写一套 clamp 常量。

**但更稳妥的口径不是「clamp 到什么值」，而是「clamp 会不会改变结论」**：

- **推演过程中先不 clamp**，而是记录触顶 / 触底事件；一旦某维触顶（trust 已打满），**这本身就是结论**——「trust 不是卡点，缺的是 safety」，而不是「再推进也没用」。本单把该信息落到了「末轮短板 / 卡点维度」列里。
- **「不可达」与「超过视界」必须分开报**。本单早期用 400 轮视界时，沉舟 / 念安 / 惊尘 / 亦舟 被误判成「不可达」；放宽到 2000 轮（`--max-horizon` 可配）后拿到 650~793 的有限值。**一个 400 轮的「不可达」结论其实是「没算够远」**，这种混淆比精度误差危险得多。
- 区间显示两侧独立：慢侧超视界只标慢侧，**不把快侧一起判死**（安然快侧 4 轮必须保留「可达」结论）。

### (c) 归档多为规则轨降级回放时，外推结论的适用边界

**任务单 §4.3 的「≈96%」核实为真**（实测 baseline 逐轮 16864 轮 / 16143 退化 = **95.7%**；场次级 429/500 = 85.8%，全库 448/646 = 69.3%）。但**边界要再收紧两层**：

1. **本归档的「退化」= 渲染降级，不等于状态推进降级**。退化轮照样跑规则事件推进状态，所以退化轮的差分**不是噪声**。按任务单口径把退化轮差分剔出主增量，会让主增量的代表样本只剩 11.5% 的轮次，代表性偏差反而更大。所以本单把「剔退化」降级为**并列口径之一**（口径 A），而不是唯一口径。
2. **归档是调试回放，438/500 场呈「前缀冻结 + 末段跳变」**（典型样本前 38 轮状态完全不动，末 12 轮一次性跳 +0.12 trust）。这种形态**天然不适合做差分中位估计**——这也正是口径 A 退化的根因。

**因此结论边界定为**：本单结论**只限定「规则轨状态机层面」的门槛可达性对账**，**不外推真实 LLM 对练表现**；外推区间是**标定参照**，不是实测结论；方向 2（门槛取值 / 深度条件是否拆分）**仍属临床拍板，另案**。
