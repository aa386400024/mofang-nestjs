## 一、背景与目标

### 1.1 背景

对照蓝图 / 交付记录 / 代码三层，找出差异点，确保文档与代码一致，架构与工程符合企业级标准，为 Phase3 混合式 BDI 灰度切换打好基础。

## 三、审计方法

### 3.1 证据口径

一律以 `src/` 实际代码 + `git show <commit>` 回溯「交付当刻」为准，**不以文档自述为准**。

```powershell
# 改动面（可复核口径）
git show --stat <commit> -- src/engine-core
git show --name-only --pretty=format: <commit>
```

### 3.2 证据强度标注

| 标注 | 含义 |
|---|---|
| **【实锤】** | 代码行级可复核，结论唯一 |
| **【静态推演】** | 由代码逻辑推导，未跑用例实测 |
| **【无法证实】** | 证据不足，单列 |

### 3.3 差异分类

| 分类 | 含义 |
|---|---|
| **① 文档写多了** | 文档声称做了，代码实际没做 |
| **② 文档写少了** | 代码做了但文档没记 |
| **③ 描述有偏差** | 做了但和说的不是一回事 |
