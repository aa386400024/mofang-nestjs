# AF-329 · 来访者文字真人度 active/off prompt A/B 实测报告（2026-11-23）

## 结论先行

生产同款 `humanization-v1` 真人度 prompt 块在当前豆包 Seed Character 上**没有产生稳定正向增益**。三次独立 A/B（每次 active / off 各 6 轮，共 36 次真实调用，0 失败）里：

- active 分支 `humanization-v1` 假设性判据 **0/3 通过**；off 分支按同一判据 **2/3 通过**。
- active 的「事件/轮」均值为 `0.444444`，低于 off 的 `0.611111`，差值均值 `-0.166667`。
- active 的「带事件轮次率」均值为 `0.333333`，低于 off 的 `0.444444`，差值均值 `-0.111111`。
- 百字密度均值 active `2.532253`、off `2.528643`，差值均值 `+0.003610`，工程上等于没有变化。
- 自我修正两分支均为 `0`；六类事件里只出现 filler 与 pause。

方向不一致：三次 active-off 的「事件/轮」差值分别是 `-0.500000`、`+0.166667`、`-0.166667`，不是单调提升。第一次 active 甚至六类事件全部归零。**结论是「当前 prompt 块不能证明有效」，不是「真人度变差」或「真人度变好」。**

## 假设性判据结果

判据版本 `humanization-v1`，门槛与 AF-328 一致：

- `event_turn_rate` 目标 `[0.15, 0.60] ± 0.02`
- `events_per_turn` 上限 `0.80 ± 0.02`
- `density_per100` 目标 `[0.20, 2.50] ± 0.05`
- `repair_per_turn` 上限 `0.10 ± 0.01`
- 最少 `5` 轮才判定

| 轮次 | off 判定 | active 判定 | active 未达标项 |
| --- | --- | --- | --- |
| 1 | pass | failed | `event_turn_rate=0` 过低；`density=0` 过低 |
| 2 | pass | failed | `density=3.636364` 超上限 |
| 3 | failed | failed | `density=3.960396` 超上限；off 另因 `events_per_turn=0.833333` 与 `density=3.289474` 未达标 |

汇总：active `0/3 pass`，off `2/3 pass`。这组数字说明**当前 prompt 块既没有把 active 拉进判据窗口，也没有让分支更稳定**；active 在第 1 轮出现完全书面化的极端，在第 2、3 轮又出现密度超上限的极端。

## 如何解释这次反向结果

1. **prompt 配额是「上限 + 不自然就不加」，不是「必须加」。** 对已经具备基础口语风格的 Seed Character，额外 526 字约束会提高「按规则克制」的优先级，模型更容易选择零事件的安全文本。
2. **单一 prompt 块同时改多层。** 场景、语域、角色声音、话轮形态、配额、事件层一次性加入，无法归因是哪一条在抑制 filler/pause；不能据此判断「真人度理论错了」。
3. **6 轮 × 单一人设的方差很大。** 三次同条件调用已经出现 0 到 3.96 的密度跨度。用单次 A/B 判定 prompt 有效或无效都会过拟合。
4. **判据本身对短样本敏感。** 6 轮里 1 个 filler 就能显著改变轮次率；密度分母是字数，短句会放大波动。AF-328 的 `humanization-v1` 是工程种子门槛，不是临床量表。
5. **测量器只覆盖四类判据。** 六类里 trailoff / elongation 只计数不判定，repair 在三次均为 0；当前语料无法证明 active 在「改口、半截话、拖长音」上有任何作用。

## 决策与后续

- **不在本轮启用 active。** 以现有证据，生产默认继续保持 off；不为「让判据通过」回头调 prompt，否则会把 A/B 变成对 6 轮样本的过拟合。
- 若继续做，下一单应把 active 块拆成单变量变体（仅配额、仅事件层、仅语域），每种变体至少 5 次配对、跨 2-3 个人设，先看**配对中位数与方向一致性**，再看单次判据。
- 判定标准应改为「active 相对 off 的事件/轮中位数提升，且 density 不越过上限」，而不是「单次 active 是否落在 humanization-v1 窗口」。
- 任何后续结果仍只能称工程文本分布指标，不能称临床真人度或疗效。

## 边界

- 合成人设、合成咨询师台词、无真实咨询内容；不写库、不启服务、不切 `RENDER_REALISM_MODE`。
- 只证明该模型、该温度、该 6 轮脚本、该 3 次采样下的文本分布；不外推到全部来访者、全部场景或生产全链路。
- 报告与原始 JSON 只保留数字与 id，不保留完整台词。
