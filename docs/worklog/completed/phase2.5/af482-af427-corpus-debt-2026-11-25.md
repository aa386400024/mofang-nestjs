# AF-482 · 修复 AF-427 台账测试对本地语料漂移的脆弱断言

## 根因

`scripts/orchestration/__tests__/af427-operator-delta-ledger.spec.mjs` 的 ④ 用例写死了：

```js
expect(markdown).toMatch(/\| empathy \| 34 \| 31 \| 3 \| 0\.2\d+ \| \d+\.d% \|/);
```

本地 `data/debug-sessions` 增长到 74 场 / 1711 轮后，表三实际 `empathy` 行为 `137 / 134 / 3 / 0.2477 / 85.4%`，测试必失败。CI 因为没有语料而跳过，导致本地与 CI 口径分裂，push 前必须临时移走语料目录。

## 修复

- 新增 `expectedCoverageRow(ledger, kind)`：直接从 `ledger.corpus.byOperator` 与 `ledger.table` 计算期望的命中轮次、单算子轮、多算子同轮、8 维幅度和与实测/系数比。
- 新增 `coverageCells(markdown, kind)`：从渲染 markdown 抓表三数据行并拆单元格。
- ④ 用例改为断言渲染行与真实统计逐格一致，并校验：
  - 单算子 + 多算子 ≤ 命中轮次；
  - 百分比分母 = 8 维幅度和 / 8 维系数和，误差 0.01。
- 两个 ④ 用例从 `if (!HAS_CORPUS) return` 改为 `it.skipIf(!HAS_CORPUS)`，语料缺失显式 skip，存在则必须校验真实行。
- 保留原测试意图：仍校验表一 / 表二 / 表三标题、empathy cap 行与零语料算子清单，不降级为只查标题。
