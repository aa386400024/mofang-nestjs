## 1. 三点待决策的第二意见（用户点名要求）

### 1.1 分组回退顺序（角色 → 依恋风格组 → 全样本）与增量分位的样本量下限

**顺序本身合理**，但要补三条约束，否则会给出「样本充足、结论无效」的假象：

1. **每一层都必须记「实际用上的是哪一层」** —— 否则读者分不清某个区间是角色自己的还是借来的。本单已实现（表 D「主增量来源层级」列）；**实测 8 个角色全部落在角色级，回退链一次都没触发**（角色级非退化差分样本 154~407 个，全部过下限）。
2. **样本量下限必须硬性化并可配** —— 差分样本 < 20 时给 25/75 分位，等于拿 min/max 冒充分位。本单已实现 `--min-samples`（默认 **20**），不足时标「样本不足 · 不出结论」，**不给单点轮次**。
3. **还要加一条「活跃轮占比」下限（建议，本单未强制执行）** —— 差分**数量**够不等于差分**信息量**够：本样本 88.5% 的轮次差分是 0，角色级活跃轮占比只有 **6.5%（亦舟）~ 11.2%（沉舟）**。建议标定批次把「活跃轮占比 < 5% → 增量估计不可用」写成硬门槛 —— 本单最低值 6.5% **勉强过线**，说明这批归档本身已经处在可用下沿。

**另外一条建议**：回退层级**不应跨角色借用增量**。角色初始基线差 3~5 倍（trust 0.18~0.65），把亦舟的增量借给惊尘会把「起点」与「速率」混算。本单按任务单实现了三层回退链，但**实测一次都没触发**；建议把回退链降级为「仅在报告里标注来源」，默认**不跨角色借**。

### 1.2 外推 clamp 上下限

**已按内核真相源取**，并建议再进一步：

- **真相源**：`src/engine-core/domain/emotion.ts` 的 `clamp01` → **[0, 1]**；`src/engine-core/cognition/state-transition.ts:784-810` 的 `applyDeltaVector` 落快照时用它 clamp `trust` / `safety` / `resistance.depth` 三维。效价走 `clampValence` → [-1, 1]（本单不涉及效价）。脚本**不 import src**（避免 build rootDir 耦合），常量逐字抄一份并在注释标注真相源文件与行号。
- **更稳妥的口径建议（比「引用 clamp01」多一步）**：外推**不该在推演过程中 clamp**，而应**先判断「触顶 / 触底会不会改变结论」**。理由：clamp 到 1.0 之后继续累加增量是无意义的（增量被吃掉），但**触顶本身就是结论** —— 「trust 已打满，缺的是 safety」比「第 331 轮」更可行动。本单已把这一点落到**末轮短板**（同盟短板 / 深度短板 / 卡点维度三分类，见表 A/B），建议标定批次**直接按短板维度**设计干预点，而不是按总轮次。
- **「不可达」与「超过视界」必须分开报**：本单早期用 400 轮视界时，沉舟 / 念安 / 惊尘 / 亦舟 全被误判成「不可达」；放宽到 **2000 轮**（`--max-horizon` 可调）后拿到 **650 / 767 / 793** 等有限值。区间显示也改为**两侧独立**（慢侧超视界只标慢侧，不把快侧一起掩掉）。

### 1.3 退化样本的适用边界

- **任务单 §4.3 的「baseline degraded ≈ 96%」核实为真**：实测 baseline **16864 轮里 16143 轮退化 = 95.7%**；且 `degraded = true` 与 `llmUsage.completionTokens = 0` **完全同数**（两个口径在这批数据上重合）。其余目录：pre96 21.7% / verify-p1d 0% / verify-prompt-version 0% / verify-route1 2.7% / verify-route1-p1d 6.0%。**场次级「全场退化」**为 baseline 429/500 = 85.8%（另 71 场是部分轮次退化），全库 **448/646 = 69.3%**。
- **边界要再收紧一层**：本归档里「退化」= **渲染降级**，**不等于状态推进降级** —— 退化轮内核照样跑规则事件、照样推进状态。所以退化轮差分**不是噪声**，它是「规则轨回放」的真实状态轨迹。任务单口径「退化轮差分单列参考、不进主增量」会让主增量只剩 **11.5%** 的轮次，**样本量虽够但代表性偏差更大**。
  - 实测证据：退化轮差分的中位 Δtrust / Δsafety / Δdepth **全部为 0**（表 E 备注列）—— 说明退化轮几乎不推进状态，这恰恰是「冻结前缀」的直接证据，而不是「样本无效」。建议把退化轮差分**提为并列口径**而不是「仅参考」。
- **更根本的边界**：baseline 目录 500 场里有 438 场呈「前缀冻结 + 末段跳变」形态（典型样本：前 38 轮状态完全不动，末 12 轮一次性跳 +0.12 trust），这不是真实对练轨迹。结论只能限定在「**规则轨状态机层面**的门槛可达性」，**不外推真实 LLM 对练表现**（T2 处置）。

## 7. 归档口径限制与隐私自检结论

### 7.1 归档口径限制（结论的适用边界）

- **规则轨回放为主**：baseline 逐轮退化率 **95.7%**、场次级全退化 85.8%；verify 批次退化率 0%~6.0%。状态推进来自规则事件序列，**不代表真实 LLM 对练轨迹**。本单结论限定为「**规则轨状态机层面**的门槛可达性对账」。
- **轨迹形态失真**：大量场次呈「前缀冻结 + 末段跳变」（典型样本前 38 轮状态完全不动，末 12 轮一次性跳 +0.12 trust）→ 这是**相邻轮差分口径退化的直接原因**（见 §2.5），也意味着**任何「每轮增量」类估计在这批数据上都会失真**。
- **时点差**：快照时点早于 S-1（端口化）与 D-2（事件拆分）落地；**门槛值未变**（0.6 / 0.35 逐字），但事件 kind 集合与词表口径与当前版本存在时点差。
- **正式批次逐轮同盟状态未落库**（`ap_practice_sessions` 为场次级元数据，`ap_practice_turns` 存来访者语义文本，不含 trust / safety / depth 序列）→ 本单输入**仅限仓库归档**；后续批次若补逐轮状态快照采集，应重跑本脚本复算。
- **各目录时点 / 轮长 / 退化率不同**，聚合按目录分层 + 总览两层；跨目录总览只作参考汇总。
- **外推假设**（报告末尾亦列出）：恒定增量速率 / 无阻抗反弹 / 无危机-破裂态 / 无跨会话衰减 / 无事件类型结构变化 / 状态 clamp [0,1]。
