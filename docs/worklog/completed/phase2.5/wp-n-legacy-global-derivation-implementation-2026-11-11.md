## 一、一句话总结

`listLegacy` 由「只返已落库行」改为：已落库行（含锚点 seed 行，场次表查不到事实也不丢）保留在前，`ap_practice_sessions` 全部场次中未标注的可标注场次补 `id=null` 派生行；`done` 仍只认 `dominant_label`，`total` = 已落库行数 + 派生场次数。批次口径（`batchId` 给定）逻辑未动。

## 六、风险与回归

- **存量 legacy 行**：30 行锚点标注在全局队列保留在前，人工列与归属列零改动；场次表中查不到事实的 seed 行不会因派生逻辑丢失。
- **一致性报告**：`consistencyAll()` 仍只遍历已落库标注行计算分母，未随本补丁改口径；全量一致性数字与 WP-N A10 基线一致。
- **去重**：同一 `debugSessionId` 在场次表多行（重跑）时只取事实表首条入派生队列；已落库行优先，派生循环用 `seen` 集合跳过，不会重复出列。
- **可标注过滤**：派生场次复用 `isAnnotatableSession`（`completed` + `turnCount>0` + `debugSessionId` 非空 + 逐字稿可取），与批次口径同一判据；`status=failed` / 逐字稿缺失场次不进队列。
- **隐私**：列表响应不携带逐字稿正文；日志只打 id / 计数 / 错误名，未新增台词日志。
