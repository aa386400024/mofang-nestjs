# AF-330 · 来访者真人度 prompt 分层消融实测报告（2026-11-23）

## 结论先行

在**正确的 steady 状态上下文**下，生产 `humanization-v1` 真人度块不是「压掉口语痕迹」，而是**把不流利事件推到过量**：

- 2 人设 × 5 分支 × 6 轮 × 2 重复，共 `120` 次真实调用，`0` 失败。
- `full` 分支两人设密度分别 `6.805556` / `7.657080`，都远高于 `humanization-v1` 上限 `2.50`；判据 `failed`。
- `event` 分支最激进：密度 `8.374672` / `7.880501`，两人设轮次率都 `1.000000`。
- `context` 分支不包含配额与事件层，仍因「话轮形态层」强制改口/停顿，把焦虑人设的 `repair/轮` 推到 `0.916667`。
- `quota` 分支是五个分支里最接近目标的，但密度仍 `4.109397` / `3.006737`，只有回避人设的一次重复落进判据窗口。
- 没有任何分支在两个人设、两次重复上稳定通过 `humanization-v1`。

**AF-329 的反向结论需要修正**：AF-329 的上下文把 `riskLevel` 写成 `'low'`，而 `resolveRealismStateBand` 把任何非 `none` 的 `riskLevel` 都判为 `risk`，于是它的 active 分支实际走的是风险轮：配额全 0、事件层不生成。AF-329 观察到的「active 六类归零」是**风险路径**，不能当作 steady 状态下的真人度效果。本报告才是 steady 状态的对照结果。

## 归因：真正的问题在「话轮形态层」，不是配额

生产块的结构是：

1. `话轮形态层` 给出一条**每轮都强制执行**的形态指令；
2. `不流利配额` 给六类合计上限；
3. `事件层` 再给一小组候选事件。

焦虑人设在 `steady` 下选中的形态是「说出口后改一次口」，句子逐字是“说出口后改一次口，用‘不对，我是说……’这种口语修正”。这是**命令式**，不是“偶尔可以”。结果 `context` 分支（没有配额、没有事件层）的 `repair/轮` 仍达到 `0.916667`，几乎每轮都改口，直接击穿 `repair_per_turn <= 0.10`。

回避人设在 `guarded` 下选中的形态是「先挡一下，说‘这个……我不太想说’，再给半句边缘信息」。结果 `context` 分支每轮都出现一个停顿，`pause` 总数为 `6` / 6 轮，密度 `6.076105`。

`event` 分支把四类候选（那个 / 省略号 / 改口 / 半截话）一次列出，虽然写“按需取用，不必全用”，模型仍接近逐项使用：焦虑 `event` 的 `filler 5 / pause 3 / trailoff 3`，密度 `8.374672`；回避 `event` 的 `pause 4.5 / trailoff 1.5`，密度 `7.880501`。

`quota` 尽力只给上限，但在 6 轮短句里，1-2 处事件已经把百字密度推到 `4.109397` / `3.006737`。这不是配额数值错，而是**短文本分母 + 每轮配额**共同放大密度。

## 对 AF-329 的修正

AF-329 的 `REALISM_AB_CONTEXT` 使用：

```ts
riskLevel: 'low'
```

`resolveRealismStateBand` 的实现是：只要 `riskLevel !== null && !== 'none'` 就判 `risk`。因此：

- AF-329 的 active 分支状态带是 `risk`；
- `buildQuotas('risk')` 返回六类全 0、`maxEvents=0`；
- `buildRealismEventPlan` 在风险轮不生成事件候选；
- 所以 active 六类归零、密度为 0，是风险路径的预期行为，不是真人度块在 steady 下的效果。

AF-329 报告里“active 分支没有产生稳定正向增益”“active 判据 0/3 pass”的**数据本身真实**，但结论标签必须改成“risk 路径对照”，不能外推为 steady 或生产 active 效果。AF-329 不应被当作“真人度 prompt 无效”的证据；AF-330 才是。

## 决策与后续

- **生产继续保持 off。** 现有 active 块在 steady 下会过量生产不流利事件，密度和修正率都远超 `humanization-v1` 上限。
- **不要先改判据门槛。** 密度 6-8 不是“阈值太严”，是 prompt 在逐轮命令模型制造事件；放宽门槛会把“刻意磕巴”判成合格。
- 下一单应改 prompt 语义，而不是继续加配额：
  1. 话轮形态从“每轮执行”改为“本轮最多允许一次，且可与配额冲突时让位”；
  2. 事件层从四类候选清单改为“最多选一个最自然的候选”，并明确“没有就不加”；
  3. 配额按连续多轮/整场设上限，不再按单轮短句设 1-2 处；
  4. 以 `quota` 分支为基线做单变量迭代，先让密度回到 `[0.2, 2.5]`，再评估轮次率。
- 任何后续结果仍只能称工程文本分布指标，不称临床真人度或疗效。

## 边界

- 合成人设、合成咨询师台词；不写库、不启服务、不改生产 prompt、不切 `RENDER_REALISM_MODE`。
- 2 人设 × 2 重复只够发现方向性过量，不够做统计显著性；不能外推到全部来访者。
- `humanization-v1` 是工程种子判据，不是临床量表。
