## 1. 旧后端在停止后短暂自启

AF-527 交付时已停止 `af281r` 的两个后端进程：

- PID `13352`：`nest start --watch`
- PID `38884`：`dist/app`，监听 3000

但合并收口期间再次复核时，3000 端口重新出现监听：

| 时间 | 进程 | 命令 |
| --- | --- | --- |
| 11:40:54 | PID 59692 | `pnpm start:dev` |
| 11:40:54 | PID 46524 | `pnpm start:dev` |
| 11:40:54 | PID 60264 | `cmd /c nest start --watch` |
| 11:40:54 | PID 10808 | `@nestjs/cli/bin/nest.js start --watch` |
| 11:41:22 | PID 51716 | `node --enable-source-maps D:\work\Project\backend\mofang-nestjs-af281r\dist\app`，监听 3000 |

父进程链指回旧 worktree 的 VS Code 集成终端（`powershell.exe`，PID 42016）。原因是旧终端保留了 `pnpm start:dev` 会话，终端恢复时重新执行，`nest start --watch` 又拉起 `dist/app`。这不是 AF-527 停止动作失效，而是“只停 watcher/app、未关闭终端”留下的重放路径。

处置：

```powershell
taskkill /PID 59692 /T /F
```

进程树全部终止，随后观察 90 秒：

- `3000` 无监听；
- `mofang-nestjs-af281r` 的 `nest start --watch` / `dist/app` 计数为 0。

运行手册已补充该处置段：`docs/runbooks/validation-environment-isolation.md`。

## 2. 状态面提交 trailer 修正

AF-527 状态面 PR #259 squash 后提交 `686c5619` 的正文是：

```text

任务 AF-527 状态面归档；无业务代码改动。\n\nTask: AF-527
```

`\n\n` 被当成字面字符串写入，`Task: AF-527` 不在独立行，`ci-task-gate` 判为 `missing-task-trailer`，integrate 推送的 Orchestration Gate 失败。

后续状态面提交按框架口径使用 `Task: none`（纯状态面），不要用 `Task: AF-xxx` 伪装业务提交；任务实现提交才写具体任务号。
