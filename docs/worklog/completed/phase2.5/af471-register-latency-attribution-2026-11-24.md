## 结论

**p95 的 +32.06% 不能由 prompt 的 +12.85% 解释；方向不是单次噪声，但机制尚未定因。**

三条可分开的事实：

1. **不是“少数慢轮”单独拉高**：active 有 75/300 轮超过 base p95（25%）；active 的前 5% 慢轮只占全部超基线时间的 20.8%，base 是 27.9%。尾部更多是整体右移，不是两三个离群点。
2. **差距随轮次累积**：前 5 轮配对中位差只有 +2ms，后 10 轮是 +723ms；p95 比值从 1.075 升到 1.415。语域块从第 1 轮就存在，前 5 轮却基本没有增量，说明“块本身多了一段字”不是主因。
3. **尾部主要发生在首包之后**：TTFT p95 只 +6.3%，post-TTFT p95 +43.7%；每 completion token 的 post 时间从 103ms 升到 139ms（+35%）。prompt token 中位从 1635 升到 1918，绝对增量约 247 token；按回归边际成本只解释 70ms，占 p95 缺口 1028ms 的 6.8%；即使按 prompt 比例线性放大，也只解释约 370ms（36%），仍不足一半。

当前最强的可检验假设是：**active 的更长 prompt/上下文使后段解码或流式段变慢，且随轮次累积**；“块内容改变了模型生成动态”仍未被排除；运行时间漂移与 p95 自身不稳定是同时存在的混杂项。

## 重复运行方差

现有数据只有每角色 1 场，不能直接观测“同一条件第二次跑”的 run-to-run 方差；下面给出三类可复算的近似：

1. **30 轮内部 bootstrap**：每场 p95 的 CV，base 均值 11.4%，active 8.3%；两者合成比值 CV 约 14.1%。
2. **10 角色中位比值 bootstrap**：中位 1.321，95% 区间 `[1.144, 1.510]`；留一角色后中位仍在 `[1.298, 1.343]`，9/10 角色方向不变。方向不是单角色撑起来的。
3. **历史 base 对照**：`af465-2026-11-24-8roles` 与本次同脚本哈希、base 无块；8 个重叠角色 base p95 本次/历史中位 1.622（范围 0.853–1.752），而 prompt token 中位只差 1.028 倍。说明**绝对 p95 在不同 run 之间可以摆动 >60%**；单次 p95 不能直接当作稳定容量结论。

因此：

- 当前 +32.1% 的**方向**有跨角色与 bootstrap 支持，不能判成纯噪声。
- 当前 +32.1% 的**幅度**不能排除 run 条件、顺序与 p95 单点不稳定；单场 p95 是 30 轮的高分位，一个 8s 慢轮就能显著改变它（本次 base 的 max 8035ms，p95 2888.7ms）。
- 以 10 角色、每角色 1 场估算，中位比值的标准误约 4.5%；每角色 2 场约 3.2%，3 场约 2.6%。**2 场是区分 15% 门槛的最低配置，3 场更适合做逐角色判断**；若两场之间 p95 比值差 >10 个百分点，应直接加到 3 场。

## 最小定向实验矩阵

不新增全量 10 角色重跑；先做 4 个代表角色 × 4 个变体 × 30 轮 × 2 次重复 = 960 轮。

角色：

- `vpt_depression_avoidant_l1`（p95 +66%，高）
- `vpt_social_anxious_l1`（p95 +58%，prompt 只 +13%，分离长度与内容）
- `vpt_trauma_disorganized_l1`（p95 +51%，高）
- `vpt_social_anxiety_avoidance_l1`（p95 -2%，负对照）

变体：

| 变体 | 处理                                     | 要回答                |
| ---- | ---------------------------------------- | --------------------- |
| V0   | base，无块                               | 同期基线              |
| V1   | 当前 active 块                           | 复现 +32%             |
| V2   | 等长中性填充，同位置、同字数、无语域内容 | 长度/位置本身是否足够 |
| V3   | 当前块移到 prompt 末尾（动态历史之后）   | 位置/前缀缓存是否主因 |

判定阈值（预注册，仍不放宽 15% 成本门）：

- V2 的 p95 增量达到 V1 的 ≥80%：主因是长度/位置，不是语域内容。
- V3 把 p95 增量压到 ≤15%：位置/前缀缓存是主因，优先改渲染顺序。
- V1 相对 V2/V3 仍保留 >15% 增量：内容诱导的生成/解码差异，进入 H5。
- 两次重复的 p95 比值差 >10 个百分点：该 cell 加到 3 次，不拿单次下结论。
- 每轮同时记录：TTFT、post-TTFT、completion tokens、post/completion token、prompt tokens、块字数/位置、服务端逐 chunk 时间戳、队列等待与 prompt cache 命中（当前产物没有这些，是本次不能定因的主要缺口）。

顺序用 ABBA 交替，base/active 不连续同向；分析仍用同期对照，不跨 run 比绝对 p95。

## 限制

- 只有一场每角色/模式；p95 是 30 轮样本高分位，天然对单个慢轮敏感。
- 产物没有服务端逐 chunk 时间戳、队列等待、prompt cache 命中率，无法把 post-TTFT 拆成模型解码、流式传输、服务端后处理。
- base/active 虽按 seed 随机顺序，但仍在同一时间窗内串行；绝对延迟随时间漂移，本报告只用同期 base 作相对对照。
- 历史 base 对照不是严格重复实验（角色覆盖、运行时间不同），只用于说明绝对 p95 的 run 间波动量级。
- 未新增模型调用、未改生产 prompt、未放宽 cost/noHarm 门槛、未修改 `src/engine-core`。
