## 〇、这 5 条是什么（定性，先读这段）

🔴 **这 5 条不是"以后有空再说"，是"能收费运营"的硬前置。**

- **WP27 / WP33 / WP39 / WP40 四条串成一条链**：能收钱（支付）→ 钱对应什么档位（会员分层）→ 档位对应什么音色（emotion 映射 / 语气词）—— 少任何一环，"会员付费"都落不了地；
- **WP29 是合规底线**：用户删除权 / 导出权 / 数据分级留存 —— 不是体验优化，是**法务与等保的硬要求**，做不出来就不能上线收 C 端的钱；
- **Phase2 的引擎能力（规则算子 / 同盟三维 / 审议层 / 记忆）已经做完**（38/43），这 5 条**与引擎能力无关**，全部卡在**外部决策与外部资质**上 —— 所以它们**从 Phase2 整体移交 Phase4**，不是"被挤掉的剩余工作"。

> ⚠️ **移交即不丢**：Phase2 封版时它们只有 roadmap §9 的一句话（"已移 Phase4"），**没有任何承接文档** —— 三个月后没人知道这 5 条欠着。本文件就是那份承接文件。
> **Phase4 开工第一件事：照着本表逐条销账**，每销一条在本表标注完成日期与交付记录。

## 二、依赖链（母版已写死，不可改）

```
WP27 billing 接真支付
  └→ WP33 会员分层 TTS
       ├→ WP39 TTS emotion 映射
       └→ WP40 TTS 内联语气词标签

WP29 数据分级留存与销毁   （独立链，与上面无关；是合规底线）
```

- **WP33 ← WP27**：tier 数据来自付费体系，没有支付就没有 tier。
- **WP39 ← WP33**：emotion 映射按"每档用什么模型"展开，先定档位才谈得上映射。
- **WP40 ← WP33**：语气词标签要按"每档模型支不支持"决定，先定档位才谈得上标签。

1. 每条 WP 开工前在 Phase4 目录单独写任务单，**交付记录落到** `docs/worklog/completed/phase4/`；
