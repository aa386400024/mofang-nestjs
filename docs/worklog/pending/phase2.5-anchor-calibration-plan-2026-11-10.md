> 写于标注进行中，标完照此执行。
> 原则：**人工标签是唯一真相，自动指标是被校准对象**。30 场不是为了"证明系统有多准"，是为了"找到自动判定跟人感觉差多少，差在哪，怎么调"。
> 日期：2026-11-10

## 一、标完后要算什么（consistency 接口已经给了三个数）

| 指标 | 接口字段 | 含义 | 达标线（工程建议） |
|---|---|---|---|
| 标签一致率 | `labelAgreement` | 人工 dominant_label vs 自动 labelOf() 命中率 | ≥70% |

## 二、逐维度偏差分析（比三个汇总数重要十倍）

30 场标完后，不要只看汇总一致率。要拆开看：

### 2.1 标签一致率拆开看：哪个标签偏得最多

```sql
-- 人工标签 vs 自动标签的交叉表
SELECT
  a.dominant_label AS human_label,
  COUNT(*) AS total,
  SUM(CASE WHEN a.dominant_label = auto_label THEN 1 ELSE 0 END) AS match,
  ROUND(SUM(CASE WHEN a.dominant_label = auto_label THEN 1 ELSE 0 END) / COUNT(*) * 100, 1) AS match_pct
FROM quality_annotation a
GROUP BY a.dominant_label;
```

**判读方法：**
- 如果 `approach` 一致率只有 30% → approach 词表太窄，真人咨询师说"我其实想聊"自动判成 neutral
- 如果 `avoid` 一致率 90% 但 `neutral` 被误判成 avoid 很多 → 词表太宽，把"我还好"也算成回避
- **结论不是"改词表到一致率 100%"** —— 词表是工程种子值，不是临床标准。一致率 70% 就够了，剩下 30% 是词表的天花板。

### 2.2 危机一致率拆开看：档位偏了还是有无判错

```sql
-- 危机有无判错的场次（人工有危机但自动说没有，或反过来）
SELECT debug_session_id, character_slug, crisis_peak_level, crisis_first_turn
FROM quality_annotation
WHERE crisis_peak_level > 0
ORDER BY crisis_peak_level DESC;
```

**判读方法：**
- 人工标了档位 2-3 的危机，自动只判出档位 0-1 → 危机词表太保守，漏判重度危机
- 人工说没危机，自动判了档位 1 → 词表太宽，把"我最近不太好"算成危机
- **档位一致率**：相邻档位（0 vs 1、1 vs 2）算"基本一致"，差两档以上才算错。因为危机强度本身就是连续谱，不是离散开关。

### 2.3 探索轮次 MAE 拆开看：是偏早还是偏晚

```sql
-- 人工探索轮次 vs 自动探索轮次的差值分布
SELECT
  debug_session_id,
  first_exploration_turn AS human_turn,
  auto_first_exploration_turn,
  (auto_first_exploration_turn - first_exploration_turn) AS diff
FROM quality_annotation
WHERE first_exploration_turn IS NOT NULL
ORDER BY diff;
```

**判读方法：**
- 如果 diff 全是正数（自动比人工晚）→ 自动探索判定太严，要等"affective_exploration"策略才算探索，真人觉得第 5 轮就算了
- 如果 diff 全是负数（自动比人工早）→ 自动太松，把"我昨天也挺郁闷的"算成探索
- **MAE ≤2 轮是可接受的**。因为探索本身就是渐进的，第 4 轮 vs 第 6 轮没有本质区别。

## 三、阈值标定：哪些参数要调，调到什么值

### 3.1 audit 脚本里的现有阈值（要列出来逐个过）

| 参数 | 当前值 | 在哪 | 调不调 | 调依据 |
|---|---|---|---|---|
| 词表覆盖率门禁 | 30% | audit 脚本 | 可能要降 | 当前 5.7%（P1d 补了词表后估计 15-20%），30% 门禁意味着文本标签永远不可用。要么降到 15%，要么承认文本标签就是辅助、不算命中率 |
| 可分辨度随机基线 | 12.5%（8 角色） | audit 脚本 | 不调 | 这是数学事实，不是阈值 |
| 可分辨度目标线 | 40% | v1 报告 | 可能要调 | 当前 22.2%，P1d + verbal_voice 后估计能到 30-35%，40% 是不是太高？ |
| 表层停留判据 | 末 3 轮全是 surface | audit 脚本 | 可能要调 | "末 3 轮"是不是太严？真人可能第 10 轮才开始探索，末 3 轮还在探索中。改成"末 5 轮"还是"最后一轮"？ |
| 危机单次披露 | 只出现 1 轮危机 | audit 脚本 | 不调 | 这是事实描述，不是阈值 |
| 降级门禁 | degraded_turns > 0 剔除 | audit 脚本 | 不调 | 数据可信度问题，没商量 |

### 3.2 标定方法（不是拍脑袋调数字）

**方法：人工标注 30 场 → 自动跑同样的指标 → 找偏差最大的那个参数 → 微调 → 再跑一遍 30 场验证 → 收敛了就定稿。**

具体步骤：
1. 先看 2.1 / 2.2 / 2.3 的偏差分布，找出**最大的那个偏差源**（不是所有参数都要调）
2. 针对那个参数，列出 3 个候选值（当前值 ±20%）
3. 用 30 场人工标注当 ground truth，算每个候选值下的一致率
4. 选一致率最高的那个值，但**不要为了一致率 100% 而过度拟合 30 场**（30 场是小样本，调到 90% 一致率就够了）

**关键纪律：**
- 词表扩容到一致率 70-80% 就停。再往上是边际收益递减，而且会让词表膨胀到难以维护
- 阈值调整要写进 audit 脚本的注释里，注明"2026-11-10 基于 30 场锚点标定"
- 调完不要覆盖旧值，在 git 里留 diff，以后 100 场数据出来可以对比

## 五、30 场标注本身的质量控制

### 5.1 标注一致性（你自己跟自己的一致性）

30 场标完后，随机挑 5 场隔一天再标一遍，看两次标注的一致率：
- 如果 ≥80% → 标注口径稳定，可以用
- 如果 <80% → 说明标注标准不清晰，要回去把每个维度的定义写得更明确

### 5.2 needs_review 标记的处理

标完后看 `needs_review = true` 的有多少场：
- 如果 >5 场（17%）→ 说明标注标准有歧义，要把存疑的场次拿出来，把模糊地带的定义写清楚
- 如果 ≤2 场 → 标注标准基本清晰，存疑场次单独标注就行

### 5.3 每个维度的定义写在标注台的 tooltip 里

用户之前提的需求："每个选择的位置加 icon，hover 提示"。
这些 tooltip 内容就是标定的依据，要写清楚：
- **探索开始轮次**：来访者第一次说出"情感层面"的内容（不是复述事件，是表达感受/渴望/害怕）
- **主导行为标签**：整场占比最多的人际行为模式（approach=靠近/求助，avoid=回避/沉默，attack=对抗/指责，appease=讨好/让步，neutral=没有明显倾向）
- **危机峰值**：0=无，1=有风险念头但有保护因素，2=有具体计划但没行动，3=有行动或强烈冲动
- **危机首次轮次**：第一次出现危机相关表达的轮次
- **该断轮次**：咨询师应该结束练习的轮次（再聊下去没有新信息了）
