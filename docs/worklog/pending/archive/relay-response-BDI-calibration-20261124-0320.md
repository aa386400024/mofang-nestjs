## 2. 四个候选的命中数与 neutral 降幅

### 2.1 判定口径（本次评估的实现约定，均为工程假设）

- **eligible 池**：只含「当前 v2 判为 neutral-only」的轮次（119 轮）。**行为事件轮不被 presence 层接管**，避免与 empathy/open_probe 等双计 delta。
- **A（疑问结构）**：文本含 `？`/`?` 或含疑问词（吗/呢/什么/怎么/为什么/哪/谁/几/多少）**且长度 ≤ 40**。
- **B（短承接）**：长度 ≤ 12 **且**以（嗯/好/是/对/行/可以/继续/你说/我在）开头。
- **C（无问句无反映的纯短句）**：无疑问结构 **且** 长度 ≤ 8 **且** 规则轨未产出行为事件（即「无反映」取规则轨判 neutral）。
- **D（组合）**：A ∨ B → `holding_present`；(C ∧ ¬A ∧ ¬B) → `cold_absent`；其余 `neutral`。

### 2.2 命中结果（pool = 119）

| 候选  | holding_present 命中 | cold_absent 命中 | 仍 neutral | 语料 neutral 率   | 降幅             |
| ----- | -------------------- | ---------------- | ---------- | ----------------- | ---------------- |
| **A** | **14**               | 0                | 105        | 58.6% → **51.7%** | −14 轮（−6.9pp） |
| **B** | 1                    | 0                | 118        | 58.6% → 58.1%     | −1 轮            |
| **C** | 0                    | **1**            | 118        | 58.6% → 58.1%     | −1 轮            |
| **D** | **15**               | **0**            | 104        | 58.6% → **51.2%** | −15 轮（−7.4pp） |

**冲突矩阵**：`A∩B = 0`、`A∩C = 0`、**`B∩C = 1`**。

→ **D 组合规则里 C 是死代码**：B 的前缀表（嗯/好/是/对/行…）恰好覆盖了 C 唯一能抓的那类短句，而 D 的优先级把 `A ∨ B` 放在前面，于是那唯一一条**本该判「缺席」的样本被判成了「在场」**。D 相对 A 的全部增益（+1）就是这一条**方向错误**的增益。

## 3. 冷场（`debug_ITUgH5VCcuZ5QXw9SBb-T`，14 轮全 neutral，cold persona）

### 3.3 筛选维度与目标维度错位（关键发现）

**A 命中的 14 轮里，带结构化标记的是 0 轮**；而 cold 场最像「在场」（结构化过渡 / 行动规划 / 显式时间线）的 4 轮，长度分别是 45 / 59 / 66 / 76 —— **全部被 ≤40 字上限排除**。

也就是说：**A 抓到的短促提问，恰恰不是最该标「在场」的那几轮；最该标的反而被上限挡在门外。** 正确的修法不是调 A 的阈值，而是换维度（用「结构化/内容承载」而不是「绝对字数」做门控）。

### 3.4 最小充分性（决定了这件事的风险等级）

**1 轮 `holding_present` 即可打破 zero_motion**：safety `0.2500 → 0.2540`（trust 不变）。这意味着：

> 只要 presence 规则在任意一场里误判 1 轮，该场的 `zero_motion` 就会从 true 翻成 false —— **指标对 presence 判定的敏感度是「轮级」的，不是「场级」的。**

### 4.1 会不会再出现 0.95 反向飙升？

**不会 —— 而且是结构性不可能。**

A/B/C/D 只产出两种标签，其 trust 增量分别是 `holding_present = 0`、`cold_absent = −0.004`：

- 四个候选的 **trust 上界 = 0.2500**（初始值，持平）；
- 只会向下走（若判为 `cold_absent`，14 轮降到 0.1940）；
- 0.95 / 1.00 只在「把冷问句映射成 `open_probe` / `empathy`」时出现，而这四个候选**不含这条映射**。

**换言之：这四个候选不会刷高信任，但它们也不会表达「冷漠」本身**（`holding_present` 的语义是「稳定在场的有效中性」，其方向偏中性偏正）。把 cold 问句标成 holding_present，得到的 BDI 轨迹是「一个在场但没有温度的咨询师」—— 与 cold persona 的设计意图相比，**它把 cold 拉向了 neutral，而不是拉向「冷漠」**。这一点是工程判断，不是临床结论。

## 6. 是否值得落成适配层 feature flag（默认关）？

### 6.1 结论：**不建议按 A/B/C/D 原样落。** 建议只落收窄版，且必须先补前置数据。

四条理由（均带数字）：

1. **B / C 在本语料近乎无产出**：各 1 次命中、且是同一次；D 里 C 是死代码。B、C 的规则形式（短应答）与 cold 现象（带结构的长问句）**不同构**。
2. **D 在唯一有效样本上判反**：那条 2 字最小应答本该是 `cold_absent`，D 的优先级把它判成 `holding_present` → safety/bond 方向错。
3. **A 的筛选维度与目标维度错位**：命中的 14 轮 0 个带结构标记，而最该标的 4 轮结构化长问句全被 40 字上限排除；另有 2/14 靠疑问词**子串**命中而非问句语法（'几乎'/'几天'/'没什么'/'哪里' 等非疑问用法是已知误命中面，本语料未触发）。
4. **风险等级最高的一条：指标敏感度是轮级的** —— 1 轮 `holding_present` 就把 safety 0.2500→0.2540、打断 zero_motion。在一个「判错 1 轮就能让指标变好」的口径上，用**未经人工标注**的规则去修指标，等于给指标装了一个可以被一次误判刷绿的开关。**这是我不建议原样落 flag 的首要理由。**

### 6.2 若仍要做（收窄版 A′/B′/C′，工程假设）
