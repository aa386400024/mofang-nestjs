## 1. 根因比任务单写的更靠里一层（实测复核）

只读复核 AF-095 那 3 场 long 会话的逐字稿（**只统计结构，不落任何台词**）：

| 指标（3 场合计） | 值 |
|---|---|
| 逐字稿里的咨询师消息 | 150 条 |
| 其中带 `<think>` 推理块的 | **116 条** |
| 其中**剥掉推理块后可见台词为空**的 | **57 条**（审计口径 53 轮，差异来自按 turnIndex 合并 + 两边皆空的轮被丢弃） |
| 咨询师消息平均原始长度 | ≈ 1400–1600 字符（装的是推理，不是台词） |

**所以"content 为空"这个判据一次都没命中过**：推理模型把 thinking 写进 `content`，
`content.length > 0` → 老代码 `raw.length === 0` 判 false → **不兜底、不降级计数**，
而且那段**内部推理被当成"咨询师说的话"喂给了来访者引擎**。

真实现场是"**content 非空，但里面只有推理**"。所以判据扩成了"**可见输出为空**"
（剥掉推理块后为空，含**未闭合**推理块 —— 那是长度截断的典型形态），否则修不到那 57 轮。

## 2. 改了什么

### 2.1 预算按会话档案分档（`reasoningEffort` 一律保持 `low`）

| 档位 | maxCompletionTokens | 理由 |
|---|---|---|
| legacy | **500（逐字不变）** | 老行为不动 |
| standard | 1024 | 30 轮会话思考量比 15 轮多，500 不够（任务单只要求 long，本单顺带给 standard 中间档） |
| long | **2048** | 治本是**抬高可见输出预算**，不是让模型想更多（想更多 = 更贵 + 更慢 + 更吃额度） |
| 重试 | **4096** | 一次失败的思考可能已花掉 500~2048，重试要留足"再想一遍 + 说出口"的空间 |

### 2.2 生成流程（`counselor-agent.service.ts`）

```
首次调用（按档案预算）
  ├─ 上游异常              → 直接兜底 + degraded（不重试：provider 层已有退避重试链）
  ├─ 可见输出非空且未截断   → 正常返回（degraded=false）
  └─ 可见输出为空 / 被截断 → 提高预算（≥4096）重试**一次**
        ├─ 异常 / 仍为空    → 兜底 + degraded
        ├─ 非空且未截断     → 正常返回（degraded=false）
        └─ 非空但仍被截断   → 保留文本 + degraded=true（**不静默当正常回复**）+ closeRequested=false
```

### 2.4 为什么 runner 不用改（任务单说"如确实需要…只改该文件"）

runner 已有通路：`counselorReply.degraded → degradedTurns / counselorDegradedTurns`。
本单把"**截断但非空**"也标成 degraded（原来它是 `degraded=false`，会被当成正常轮次混进数据），
于是**空输出与截断从此自动进降级计数** —— 不需要改 runner，核对后确认无需改，故未动该文件。
