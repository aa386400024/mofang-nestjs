## 3. P1 —— 未闭合的漏洞（阻断"开启机制"，不阻断本次归档）

### P1-1 念安是**浮点发丝**判定的 `avoidanceDominant` → 哀伤角色被静默排除出探索与后段分支

**证据**

```
念安 (vpt_grief_avoidance_l1)   avoid_pain=0.68  understood=0.58  差值=0.100  → dominant = true
0.68-0.58 = 0.10000000000000008882   > 0.1  →  true
```

- 比较发生在 `src/engine-core/cognition/intention-planner.ts:192`：`avoidPainWeight - Math.max(understoodWeight, acceptedWeight) > thresholds.avoidanceMargin`（margin = 0.1，`alliance-config.ts:196`）。
- 0.68 − 0.58 在 IEEE-754 下是 **0.10000000000000008882**（比 0.1 高 8.9e-17），因此 `> 0.1` 成立 → **念安也被判 dominant**。
- `avoidanceDominant=true` 会同时否决**后段分支**（`intention-planner.ts:309-317`）与**探索分支**（`:357-368`）→ 念安与惊尘一样恒落 `recounting`。
- 探针 3 复算 10 个角色：`avoidanceDominant=true` 共 **3 个** —— 惊尘（差值 0.720）、builtin_avoidant_l1（0.450）、**念安（0.100 发丝）**。

**为什么这是 P1**

1. **披露缺口**：交付记录 §2 只点名了惊尘（"惊尘 … 恒为 recounting"），§3 的 gateResults 写"3 个角色 `avoidanceDominant=true`"却没列出是哪三个 —— 读者会以为第三个是别的角色。**念安是哀伤/未完成哀悼的角色**，它的 `safe_grief→understood 0.58` 恰恰是为了让"被理解"通道可用，现在被 `avoid_pain 0.68` 以 8.9e-17 的差值一票否决 —— 这与"惊尘创伤解组不适合深入"是**性质完全不同**的情况，却得到了同样的处理。
2. **脆性**：差值恰好压在 margin 上，任何权重微调（例如愿望演化机制一旦开启，把 `avoid_pain` 抬 0.001）或标定改动，都会让念安在"恒 recounting"与"可探索"之间翻转；反过来，把 `understood` 抬高 0.001 也同样翻转。**这是不可运维的判定**。
3. **审计不可见**：`bin/bdi-readiness-audit.ts` 的 `avoidanceDominant` 列只输出"是/否"，差值按 `toFixed(2)` 打印 → 0.100 与 0.10 看不出区别（实测 `0.100`）。

**最小修复建议**（两条都要，需主控拍板，因为涉及比较语义）

- **比较加容差**：`intention-planner.ts:192` 改为 `diff > thresholds.avoidanceMargin + 1e-9`，**审计 CLI 同步改**（`bin/bdi-readiness-audit.ts` 新增的 `avoidanceDominant` 行），否则审计与内核口径漂移。惊尘（0.72）、builtin_avoidant（0.45）不受影响，念安恢复为非 dominant。
  - ⚠️ 这属于"12 个决策阈值"的**比较语义**变更，任务单红线写的是"不改阈值数值" —— 数值确实没改，但比较口径变了，建议走一次显式签批并在 `deviationTable` 记一条。
- **披露补全**：交付记录 §2 与审计输出都应**点名三个角色**，并把差值打到 4 位小数，让"发丝判定"可见。

### P1-2 否定后缀规则误杀"没有人 / 并不"类真实觉察，且"不"与"并不"口径不一致

**证据**（探针 2）

```
保留  "我意识到不需要别人认可"
排除  "我意识到并不需要别人认可"      ← 同一句话加个"并"就被丢掉
排除  "我意识到没有人在意我"          ← 临床上很典型的一句觉察
排除  "我意识到没有人真正关心我"      ← 同上
```

- 规则在 `state-transition.ts:1356-1357`：`suffix.startsWith(token)`，`BELIEF_NEGATION_SUFFIX_TOKENS`（`:1163`）= `['从来没有','从来没','并没有','并没','没有','从未','从没','并不','没','未']`。
- 问题在中文的**否定辖域**：这里被否的是"有/需要"（存在与需要），**不是**"意识到"。`我意识到没有人真正关心我` 是一句典型的自我觉察（"我意识到没有人真正关心我"），正是这个机制存在的理由，却被整句丢掉。
- 同时暴露出**口径不一致**：`不`（单字）**不在**后缀表里 → `我意识到不需要…` 保留；而 `并不` **在**表里 → `我意识到并不需要…` 被排除。同一语义、两种结局，取决于一个副词。
- 方向：这是**信号损失**（假阴性），不是临床反转，所以不是 P0；但它系统性地削弱的正是"核心未被看见"这一类最有价值的觉察。

**最小修复建议**（同时保住现有 30 条矩阵口径）

把"否定紧邻标记"收紧成"**否定紧邻标记动词**"，并把 hedge 型标记单独处理：

```ts
/** 否定的是标记动词本身（"没有意识到" / "没发现"）→ 不是觉察. */
const NEGATED_MARKER = /(没有|没|不|未|并不|并没|从没|从未|从来没有)\s*(意识到|发现|觉察到|注意到|开始意识到)/;
/** hedge 型标记（我似乎 / 我好像 / 原来我）本身不含觉察动词 → 单独不算觉察. */
const HEDGE_ONLY_MARKER = /^(原来我|我好像|我似乎)/;
```

判定顺序：`NEGATED_MARKER` 命中 → 排除；否则若句子里的标记只有 hedge 型（`SELF_REFLECTION_MARKERS` 命中项里没有 `意识到/发现/觉察到/注意到`）→ 排除；否则保留。

- 逐条核对现有 30 条矩阵：该规则下 **8 条否定全部仍然排除**（含 `我似乎并不觉得自己被排斥` —— hedge 型且无觉察动词 → 排除）、`我发现我并不开心` 与 `我意识到自己不想再讨好了` 仍然保留 ✅。
- 副作用：`我似乎觉得自己被排斥`（有 hedge 无觉察动词）会从"保留"变"排除" —— 这是口径收紧，属临床决定，建议连同 `我好像她总是这样` 一起请督导拍板。

### P1-3 展开分支的序号守卫现在**只能压制、不能防膨胀** → 重启/接续会话后合法展开被静默丢弃

**证据**（探针 1，场景：内核快照里 `lastObservedAtVisitorSeq=12` 已持久化，而适配层序号从 1 重新开始）

```
正常序列:      conf=0.65 seq=2
重启后(旧 seq=12, 新 seq=1) 展开 -> conf=0.65 ev=2   ← 期望强化到 ~0.70，实际被静默跳过
```

- 守卫在 `state-transition.ts:1239`：`if (seq !== undefined && lastSeq !== undefined && seq <= lastSeq) return;`
- 关键结构变化：**在"复读不强化"语义下，膨胀已经不可能发生**（复读走 `:1217` 分支，从不动置信度）—— 所以这行守卫**已经失去了它唯一的存在理由**，只剩压制能力。
- 而它会误压制：`lastObservedAtVisitorSeq` 随 BDI 快照**持久化**（`beliefs.ts:50`），而门面的来访序号是**进程内**的（`turn-render-orchestrator.ts:850`、`:897`）。后端重启或会话接续后：
  - `restoreHistory` 用"历史里来访腿的条数"当序号起点（`:897`）→ 与内核已记住的序号**不在同一编号空间**；
  - 未走 `restoreHistory` 的普通接续 → 门面从 1 重新计数，而内核仍记着旧值。
- 结果：在本地序号追平持久化序号之前，**来访的每一次"展开"都被静默丢弃**（不强化、连 `statement` 也不更新）。方向是保守的（不会假阳性），但它是**静默的功能失效**。

**最小修复建议**（二选一，推荐前者）

- **(a) 直接删掉这行守卫**（`:1239`）。理由：复读不强化之后，本分支已无膨胀风险；删除后跨重启的展开恢复可用，且不引入新的假阳性路径。保留 `:1217` 的复读分支作为唯一防线即可。
- **(b) 让序号空间跨重启单调**：会话侧把序号起点改为 `max(历史来访腿数, 持久化的 lastObservedAtVisitorSeq + 1)`，或引入会话级持久化单调计数器。成本更高，且需要把序号语义从"进程内"升级为"会话级"。

> 另：AF-358 的交付记录 §5 `contractChecks` 写 `seq-monotonic | pass`，但按上面的证据，"会话内单调"在重启/接续路径上**并不成立**（是进程内单调）—— 建议把该行的措辞改准。

## 5. 待判断：这次"复读 vs 展开"的临床口径站得住吗？

**我的判断：站得住，且是这次返修里最正确的一个决定。** 三条理由：

1. **复读是频次信号，展开才是深度信号。** 把"同一句被说了两次"当成"已整合"，在测量上就是把 `frequency` 误当 `depth`。AF-358 把这两件事分开（复读只刷新观察痕迹、展开才改置信度），概念上是对的。
2. **逐字复读的常见成因恰恰指向"未整合"。** LLM 来访者的模板化复读、来访者被咨询师复述后的防御性重复 —— 这两类都更接近"固着 / 反刍"，而不是"领悟"。把它们接到 `insight` 分支上，是整条链上**最容易被督导质疑、也最容易造成"系统替来访宣布领悟"**的接法。AF-357 的原实现正好踩在这个接法上。
3. **它同时把 P0-1 从"防御"变成"语义"。** 复读不强化之后，"同一句在降级轮被重复读到"这件事**根本不可能**再抬高置信度 —— 修复不再依赖序号守卫这种工程补丁，而是从语义上不成立。这比单纯的加序号更稳。

**但要补两条护栏，否则"站得住"只成立一半：**

- **护栏 A（对应 P1-4）：给 `insight` 一个明确的督导口径。** 现在"一句陈述 + 一次展开"就进 `insight`（第 8 轮起）。方向对，但请在督导纪要里写死："`insight` 分支 = 来访把一条觉察**展开了**"，而不是"来访已完成整合"。若督导认为证据不足，再讨论是否要求"展开次数 ≥ 2" —— 那是标定决策，不该由实现侧定。
- **护栏 B（对应 P2-2）：别把复读信号一起扔了。** "来访又一次回到同一主题"是真实且有临床意义的（固执 / 未加工 / 反刍）。现在的实现把它丢得干干净净（`evidenceCount` 不涨、置信度不动、无任何字段）。建议**保留计数但不改置信度**：让 `evidenceCount` 记"被观察次数"（含复读）、另设一个字段记"被展开次数"，或者反过来 —— 无论哪种，都不触碰已定的置信度语义。这样督导视图能看见"这个主题被反复提到 N 次但从未被展开"，这恰恰是最值得督导看一眼的形态。

**还有一条实现口径要提醒督导**（不是缺陷，是语义边界）：当前"展开"是**纯文本包含**判定（`findExpansion`，`state-transition.ts:1258-1272`，要求新句规范化后包含旧句且更长）。两个方向的偏差同时存在：

- **过宽**：旧句若是通用片段（"我需要…"），后续不相关的句子也可能被并成同一条；
- **过窄**：同一件事换个说法（不换词）不会被识别为展开。

建议督导标注时把"展开"标成**主题级**（是否在谈同一件事），而不是逐字包含 —— 否则标出来的口径和实现的口径会对不上。
