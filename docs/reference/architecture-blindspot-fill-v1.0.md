# 心塑终局架构：盲区补全与融入方案

> 原件转写（PDF → Markdown）。本文是盲区清单依据；哪些纳入、阶段归属与工程裁剪以工程母版 [`ai-engine-roadmap-v1.1.md`](../architecture/ai-engine-roadmap-v1.1.md) 与装配 backlog 为准，冲突以母版为准。

## 总原则

所有补充能力**不改动原五层架构的分层边界与主会谈流水线**，全部以「内部子模块扩展、字段新增、旁路异步补充、机制完善」的方式融入现有体系，严格遵循开闭原则，不推翻原有设计骨架。

覆盖五大类共 14 项盲区，每项均包含：现状缺口 → 风险影响 → 详细落地方案 → 架构融入位置 → 数据结构变更 → 落地优先级。

### 整体融入总览（对应原五层架构）

| 原架构层级 | 新增 / 扩展内容 | 对原有逻辑的侵入性 |
|---|---|---|
| 接入层 | 非语言事件标准化、流式断连重连协议 | 低，仅扩展事件类型与协议 |
| 编排层 | 事务边界定义、状态幂等机制、会话分支状态机、熔断降级状态对齐 | 中，扩展工作流节点，不改变主链路顺序 |
| 核心引擎层 | BDI 新增咨询同盟模型 / 时间衰减算子 / 非语言算子；伦理引擎新增学员风险检测 / UGC 运行时风控；记忆引擎新增分层压缩；新增旁路「实训评估引擎」 | 中，均为引擎内部扩展，对外接口不变；新增引擎为旁路异步，不进主链路 |
| 数据服务层 | 状态字段扩展、分支标识、角色版本规则、数据分级留存策略 | 低，新增字段与表，原有数据模型兼容 |
| 基础设施层 | 归档存储策略、数值边界监控 | 低，运维侧补充，无业务侵入 |

## 一、专业仿真层面：真实咨询细节补全

定位：强化长程仿真的专业真实感，全部内聚于 BDI 引擎内部，不改变外层调用方式。

### 1.1 咨询同盟（工作同盟）独立建模

**现状缺口**：当前架构中，信任、移情、阻抗散落在 BDI 各字段中，没有独立的「咨询同盟」维度与演化模型。真实长程咨询中，咨询同盟是独立的核心预测变量——同盟建立、破裂、修复有自身的规律，不是单次情绪与阻抗的简单叠加。

**风险影响**：长程个案仿真会出现「关系变化不连续」：一次失误不会造成同盟破裂，持续共情也不会累积同盟深度，咨询关系的起伏感缺失，专业真实感不足。

**详细落地方案**：

（1）同盟三维度定义（存入会话动态状态）

| 维度 | 含义 | 取值范围 |
|---|---|---|
| trust_level 信任度 | 来访对咨询师善意、能力的相信程度 | 0–1 |
| safety_level 安全感知 | 来访在咨询中的安全感、被接纳感 | 0–1 |
| bond_level 同盟联结 | 双方对咨询目标、工作方式的共识程度 | 0–1 |

综合同盟得分 = 三维度加权均值，作为所有关系类算子的基础输入。

（2）专属算子库（BDI 事件算子库新增分组）

1. **同盟建立算子**
   - 触发事件：准确共情、真诚接纳、设置稳定、信守承诺；
   - 效果：三维度缓慢提升，提升速率受依恋类型调节（回避型提升慢，安全型提升快）。
2. **同盟破裂算子**
   - 触发事件：评判、说教、越界、失信、打断创伤表达；
   - 效果：安全感知骤降，信任度下滑，阻抗大幅反弹；破裂程度分「裂痕」「破裂」两级。
3. **同盟修复算子**
   - 触发事件：咨询师道歉、真诚面质、修复设置；
   - 效果：修复速率远慢于破裂速率，且无法完全回到破裂前水平，符合真实咨询规律；
   - 关键规则：破裂越严重，修复的边际成本越高，避免「一句道歉立刻和好」的失真。

（3）与现有能力的联动：

- 同盟水平直接调节阻抗下降速率：同盟越好，相同共情带来的阻抗下降越明显；
- 同盟水平影响记忆开放度：同盟越高，越容易召回深层创伤记忆；
- 伦理盲盒中「关系破裂」场景，直接基于同盟模型实现标准化触发。

**架构融入位置**：核心引擎层 → BDI 认知仿真引擎 → 内部新增「咨询同盟子模块」；角色内核新增依恋类型等基线参数（静态只读）；会话动态状态新增同盟三维度字段；算子库新增「同盟算子分组」，随会谈事件同步执行，对外输出接口不变。

**落地优先级**：Phase 2 专业增强期落地。

### 1.2 沉默、非语言互动与节奏仿真

**现状缺口**：当前主流水线默认「咨询师发一句话 → AI 回一句话」的文本一来一回模式，事件体系只有说话事件，没有沉默、停顿、打断、语气等非语言互动。真实咨询中大量时间是沉默，沉默等待是核心技术，缺失会导致仿真「话密、节奏快」，不符合临床真实感。

**风险影响**：语音实训场景体验失真；咨询师无法练习「沉默等待」技术；来访反应永远是立刻回复，没有思考、犹豫的过程。

**详细落地方案**：

（1）会谈事件体系扩展：接入层新增标准化非语言事件类型，全部纳入事件总线：

| 事件类型 | 触发场景 |
|---|---|
| SILENCE 咨询师沉默 | 咨询师超过设定时长未发言，系统自动触发 |
| INTERRUPT 咨询师打断 | 咨询师在来访发言过程中发送新消息 |
| TONE_SHIFT 语气变化 | 语音模式下识别到语气、语速显著变化 |

（2）BDI 行为策略扩展：behaviorStrategy 新增可选值：

- **ACTIVE_SILENCE 主动沉默**：不说话，用沉默表达防御 / 思考 / 情绪；
- **PAUSE_THEN_SPEAK 停顿后开口**：先停顿几秒，再说话；
- **INTERRUPT_RESPONSE 被打断反应**：生气、退让、停止说话。

同时新增对应算子：

- 沉默事件算子：根据同盟水平与当前议题，决定来访是主动开口、继续沉默、还是产生负性情绪；
- 打断事件算子：根据阻抗与同盟水平，决定来访是停止、反驳、还是阻抗上升。

（3）渲染层适配：

- 输出格式扩展：支持 `[silence:3s]` 这类时间标记，前端语音播放时对应留白；
- 非语言描述注入：根据行为策略自动生成「（沉默片刻）」「（声音变小）」等动作描述；
- 语速节奏控制：阻抗越高、情绪越波动，语速越慢、停顿越多。

**架构融入位置**：接入层（流式会话网关扩展事件识别与沉默超时检测）；编排层（事件总线新增事件类型，工作流兼容非语言事件）；核心引擎层（BDI 算子库扩展，多模型渲染引擎扩展输出格式）。

**落地优先级**：Phase 2 落地基础版，Phase 3 语音场景完善。

### 1.3 会谈间隔的自然演化机制

**现状缺口**：当前长程接续是「原样加载上一轮状态」，相当于时间冻结。真实咨询两次会谈间隔数天到数周，情绪会自然回落、阻抗会自然回弹、记忆会自然遗忘，不是静止不变的。

**风险影响**：长程个案的真实感打折：上一轮吵崩了，下周见面怒气全消；上一轮刚建立的信任，隔两周依然满格，不符合心理规律。

**详细落地方案**：

（1）时间衰减算子（BDI 新增）：会话恢复时，先执行一次「间隔衰减计算」，根据间隔时长对各状态变量做差异化衰减：

| 状态变量 | 衰减速率 | 规则说明 |
|---|---|---|
| 情绪强度 | 快（半衰期 ≈ 3 天） | 愤怒、难过等激烈情绪消退最快 |
| 阻抗水平 | 中（半衰期 ≈ 14 天） | 防御会慢慢回弹，不会一直保持低阻抗 |
| 短期信念置信度 | 慢（半衰期 ≈ 30 天） | 信念松动效果会缓慢回落 |
| 同盟水平 | 极慢（半衰期 ≈ 90 天） | 建立的联结不会快速消失 |

（2）反弹效应补充：

- 若上一轮结束时同盟处于「破裂 / 裂痕」状态，间隔期阻抗不会自然下降，反而会小幅上升（负性记忆强化）；
- 若上一轮结束时同盟良好，间隔期信任缓慢小幅回落，回到「日常基线」。

（3）记忆自然遗忘：间隔期内，短时记忆自动降级，不重要的记忆重要度衰减，符合人类记忆的遗忘曲线。

**架构融入位置**：核心引擎层 → BDI 认知仿真引擎 → 新增「时间衰减算子」；编排层（会话恢复工作流中，进入主流水线前先执行「间隔状态更新」节点）；数据层（会话状态记录上次活跃时间，作为衰减计算依据）。

**落地优先级**：Phase 2 落地，长程个案核心体验。

## 二、工程可靠性层面：状态一致性保障

定位：解决流式、异常、降级场景下的状态漂移问题，全部在编排层与数据层完善，不改动核心引擎逻辑。

### 2.1 状态事务边界与幂等机制

**现状缺口**：当前流水线串行执行，BDI 算完就更新状态，再渲染输出。若渲染失败、网络中断，会出现「状态已经改了，但用户没看到回复」的半轮失败问题；重试会导致状态重复叠加，引发人设漂移。

**风险影响**：用户感知到来访「莫名其妙变了」，状态不一致 bug 难以排查，长程会话累积误差越来越大。

**详细落地方案**：

（1）单轮三阶段事务划分：

1. **预计算阶段（内存态，可全回滚）**：事件解析 → BDI 推理 → 轨迹修正 → 记忆召回 → 伦理校验；所有计算在内存完成，不更新任何持久化状态，只输出预计算结果。
2. **状态提交点（原子提交）**：伦理校验通过、最终意图生成完毕后，原子更新 Redis 中的会话热状态，生成唯一 round_id，标记本轮状态已生效；提交点之后渲染失败不回滚状态——因为来访的心理反应已经发生，只是没说出口。
3. **异步落库阶段（最终一致）**：渲染完成后，异步将本轮完整状态、对话明细写入 PG，归档审计。

（2）幂等保障：

- 每一轮对话生成全局唯一 round_id，所有状态更新、算子执行、落库操作全部绑定 round_id；
- 相同 round_id 重复请求，直接复用已提交的意图结果，不重复执行 BDI 计算，不重复更新状态；
- 客户端重试必须携带 round_id，服务端自动去重。

**架构融入位置**：编排层（工作流拆分「预计算」「提交」「落库」三个节点，明确事务边界）；数据服务层（Redis 热状态更新保证原子性，所有写操作带幂等键）。

> 工程裁剪（母版）：Phase1 单实例内存态只做轻量 round_id 去重 + 内存预计算；Redis 原子提交 + PG 异步落库三阶段事务留待多实例/终局形态。

**落地优先级**：Phase 1 必须落地，核心可靠性底座。

### 2.2 流式输出的断连状态对齐

**现状缺口**：默认整轮跑完才落库，但 WebSocket/SSE 流式传输中，用户收到一半断网、刷新页面是高频场景。此时用户看到半句话，后端状态是否更新不明确，重连后会出现前后不一致。

**风险影响**：用户侧体验断裂，服务端状态与用户感知不一致，引发逻辑 bug 与投诉。

**详细落地方案**：

（1）状态生效规则：

- 流式输出过程中，仅 Redis 热状态已提交，PG 持久化不执行；
- 只有当服务端检测到「完整文本输出完毕 + 客户端已接收确认」，才触发异步持久化；
- 若流式输出中断，本轮状态保留在 Redis，但不标记为「已完成」，不进入历史轮次。

（2）断连重连机制：

1. 客户端重连时，携带最后一次完整接收的 round_id；
2. 服务端校验：若本轮已完整输出 → 补发完整文本；若本轮输出中断 → 从断点继续推送剩余流；若本轮未提交 → 回滚到上一轮完整状态，重新执行本轮；
3. 极端情况：客户端丢失上下文，服务端以最后一次 PG 持久化的完整轮次为准，保证状态可回溯。

**架构融入位置**：接入层（流式会话网关实现断点续传、重连协议）；编排层（状态机新增「输出中」「已完成」细分状态）。

> 工程裁剪（母版）：语音 TTS 边播边合成、已播出不可撤回，本期不做语音断点续传；只保「断流不重复叠加 + 可重发新一轮」。

**落地优先级**：Phase 1 必须落地，流式场景基础保障。

### 2.3 降级模式的状态对齐机制

**现状缺口**：方案提到 BDI 异常时降级为纯 Prompt 模式，但未定义降级期间的状态如何处理。若降级时不更新状态，恢复后逻辑断层；若更新状态，纯 Prompt 输出无法拆解出结构化心理变化。

**风险影响**：降级成为状态崩坏的入口，一次故障导致整个长程会话逻辑报废。

**详细落地方案**：

（1）两级降级定义：

| 降级等级 | 触发条件 | 状态处理规则 |
|---|---|---|
| 轻度降级（渲染降级） | 主模型故障，切换兜底模型 | BDI 正常计算，状态正常更新；仅渲染层换模型，用户无感知 |
| 深度降级（BDI 降级） | BDI 引擎 / 核心链路故障 | 切换纯 Prompt 兜底，暂停 BDI 状态更新，所有对话打降级标记 |

（2）深度降级的状态回溯同步：

1. 降级期间，仅保存对话原始文本，BDI 状态冻结在降级前的快照；
2. 核心引擎恢复后，自动触发「状态回溯任务」：将降级期间的所有对话批量输入 BDI 引擎，一次性计算出状态变化，补全中间轮次的 BDI 快照，补全完成后会话恢复正常运行；
3. 若降级轮次过多（超过 5 轮），提示用户会话状态可能存在偏差，可选择回退到降级前节点。

**架构融入位置**：编排层（熔断降级组件扩展降级等级，状态机新增「降级中」状态）；核心引擎层（BDI 新增批量回溯接口，支持多轮对话一次性计算状态）。

> 工程裁剪（母版）：深度降级仅作为引擎整体故障的最后保险，恢复后用纯规则重放补快照，Prompt 结果不反哺 BDI 状态，降级轮次不计考核；批量回溯实现放 Phase2。

**落地优先级**：Phase 1 定义降级规则，Phase 2 完善回溯能力。

## 三、合规安全层面：风险与数据边界补全

定位：补齐心理咨询场景特有的合规风险，全部扩展伦理安全引擎与数据治理能力。

### 3.1 学员自身心理风险兜底

**现状缺口**：伦理引擎主要检测「学员专业越界」和「来访输出风险」，未覆盖「学员自身心理风险」——实训中学员代入自身创伤、流露抑郁 / 自伤意念的场景非常高频，平台有安全保障义务。

**风险影响**：合规红线风险，极端情况引发安全事故与法律责任。

**详细落地方案**：

（1）伦理引擎新增检测分支：输入侧检测新增「学员自我暴露风险」维度，与「专业伦理越界」并行检测：

| 风险等级 | 判定标准 | 处置策略 |
|---|---|---|
| 低风险 | 一般性情绪倾诉、生活困扰 | 打标签记录，会话正常继续，后台静默监测 |
| 中风险 | 明显抑郁情绪、创伤表达、持续自我否定 | 弹出温和关怀提示，会话继续，提升监测等级 |
| 高风险 | 明确自伤 / 自杀意念、伤害计划、极端危险表达 | 立即阻断实训会话，弹出危机干预热线与转介资源，记录审计日志，触发人工复核 |

（2）核心规则：

- 检测只针对学员输入，不影响来访仿真逻辑；
- 高风险阻断后，不销毁会话，仅暂停实训模式，用户确认后可返回但继续重点监测；
- 所有风险事件永久留存审计日志，不可删除。

**架构融入位置**：核心引擎层 → 伦理安全引擎 → 新增「学员风险检测子模块」；编排层（工作流中伦理校验节点扩展分支，高风险直接跳转阻断流程）。

**落地优先级**：Phase 1 必须落地，合规硬底线。

### 3.2 UGC 角色运行时风控

**现状缺口**：UGC 角色仅做入库前静态审核，运行时可能通过对话引导逐步输出违规内容；或有人刻意制作「擦边角色」，表面正常、深入对话后触发风险。

**风险影响**：静态审核漏网的违规角色，在运行中产生合规风险，且难以发现。

**详细落地方案**：

（1）角色行为画像机制：为每个角色建立运行时风险画像，持续统计：

- 风险输出频次：伦理拦截触发次数、违规关键词命中次数；
- 用户举报率：该角色下的用户举报数量；
- 风险偏离度：输出内容与角色设定的合规偏差值。

（2）自动处置规则：

| 风险等级 | 处置方式 |
|---|---|
| 低风险 | 标记预警，人工抽查 |
| 中风险 | 限制曝光，进入复审队列 |
| 高风险 | 自动下架，冻结该角色所有会话，触发人工审核 |

（3）版本更新回溯：角色大版本更新后，自动抽样运行标准测试用例，校验风险水平变化，避免「正常角色更新后变违规」。

**架构融入位置**：核心引擎层 → 伦理安全引擎 → 新增「UGC 角色运行时风控子模块」；数据服务层（新增角色行为统计表，纳入数据治理）。

**落地优先级**：Phase 2 UGC 体系上线时同步落地。

### 3.3 数据分级留存与合规销毁

**现状缺口**：方案提出「全量留痕、全链路审计」，但未明确不同数据的留存周期与销毁规则。心理咨询对话属于高度敏感个人信息，无限期留存不符合「最小必要」与《个人信息保护法》要求。

**风险影响**：等保审查、监管检查不通过；用户数据权益无法保障。

**详细落地方案**：

（1）四级数据留存策略：

| 数据类别 | 内容示例 | 留存期限 | 到期处理 |
|---|---|---|---|
| 审计风控类 | 风险事件、操作日志、伦理拦截记录 | 永久留存 | 匿名化归档，不可删除 |
| 状态评估类 | BDI 快照、评分数据、能力档案 | 3 年 | 脱敏后归档，去除个人标识 |
| 原始对话类 | 对话文本、语音记录、记忆原始内容 | 1 年 | 匿名化归档，可申请删除 |
| 临时缓存类 | Redis 热状态、临时计算数据 | 会话结束后 7 天 | 自动清除 |

（2）用户数据权利保障：

- 支持用户主动删除自身实训数据：删除后同步清除对话、状态、记忆数据，仅保留匿名化审计日志；
- 支持数据导出：用户可导出自己的全部实训数据；
- 所有数据操作留痕，纳入审计体系。

**架构融入位置**：数据服务层（数据治理组件新增生命周期管理）；基础设施层（新增冷归档存储，配置自动过期清理策略）。

> 工程裁剪（母版）：上表年限为建议值，非法定统一硬性年限，落地前待法务 / 等保确认，不写死。

**落地优先级**：Phase 2 正式运营前落地。

## 四、业务生态层面：产品能力架构落点

定位：补齐产品九层蓝图中缺失的技术落点，全部为新增模块，不侵入主仿真链路。

### 4.1 独立实训评估引擎

**现状缺口**：产品九层蓝图有「多流派评分标尺」，但技术方案中仅说明 BDI 输出支撑评分，评分模块本身没有明确架构落点，职责边界模糊。

**风险影响**：评分逻辑散落在业务代码中，难以迭代多流派标尺；无法支撑督导复盘、能力档案等核心功能。

**详细落地方案**：

（1）模块定位：核心引擎层的旁路异步引擎，不进入主对话同步链路，通过事件总线消费数据，完全解耦。主会谈流水线不变（事件→BDI→轨迹→记忆→伦理→渲染）；评估引擎并行消费：每轮完成后，异步拉取 BDI 快照、对话内容、伦理标签进行打分。

（2）评估维度：

1. 基础技术维度：共情、提问、边界、倾听等通用能力，全流派通用；
2. 流派专项维度：CBT / 精神分析 / 人本 / 家庭治疗等流派专属标尺，可配置开关；
3. 伦理合规维度：基于伦理引擎标签，统计合规与违规点；
4. 过程维度：同盟变化曲线、阻抗变化趋势、议题推进效率。

（3）输出产物：

- 实时侧边提示：低优先级，不打断对话；
- 会后完整复盘报告：得分、亮点、问题点、改进建议；
- 能力成长档案：长期数据沉淀。

**架构融入位置**：核心引擎层 → 新增「实训评估引擎」，与原有五大引擎平级，旁路异步运行；编排层（回合完成事件推送至事件总线，评估引擎订阅消费）；数据服务层（新增评分、档案相关数据表）。

**落地优先级**：Phase 2 落地基础版，Phase 3 完善多流派标尺。

### 4.2 会话分支与状态回退能力

**现状缺口**：会话状态机为线性向前设计，不支持回退、分支。而督导复盘、重练、多方案对比是 B 端核心需求——「倒回到第 5 轮，换一种回应方式再练」是高频场景。

**风险影响**：督导生态、B 端机构场景的核心功能无法实现，产品生态闭环缺失。

**详细落地方案**：

（1）状态机扩展：分支快照机制

1. 每一轮对话完成后，自动生成完整状态快照（BDI 全量状态、记忆、轨迹、同盟）；
2. 用户发起「回退到第 N 轮」时，基于第 N 轮的快照，创建一个新的会话分支；
3. 原分支完整保留，新分支独立演进，互不干扰；
4. 支持同一主会话下多个分支并存，可切换查看对比。

（2）分支类型：

| 分支类型 | 应用场景 | 数据规则 |
|---|---|---|
| 练习分支 | 学员自行回退重练 | 独立存储，不计入主档案 |
| 督导分支 | 督导批注、示范对话 | 标记督导身份，纳入档案 |
| 考核分支 | 正式考核会话 | 不可回退、不可编辑 |

（3）限制规则：正式考核会话默认关闭分支与回退能力，保证考核严肃性；分支数量设上限，避免数据膨胀。

**架构融入位置**：编排层（会话状态机扩展分支管理能力）；数据服务层（会话状态表新增 branch_id、parent_round_id 字段，快照独立存储）。

**落地优先级**：Phase 2 B 端工作台上线时落地。

### 4.3 角色版本兼容机制

**现状缺口**：角色内核有版本管理，但未定义「进行中长程会话」与「角色版本迭代」的兼容规则。角色更新后，正在进行的长程会话是否升级、如何升级没有标准。

**风险影响**：角色迭代导致长程会话前后人设不一致；bug 修复无法及时生效；UGC 角色越活跃，版本冲突问题越严重。

**详细落地方案**：

（1）语义化版本规则（主版本.次版本.修订号）：

| 版本类型 | 变更内容 | 运行中会话处理 |
|---|---|---|
| 主版本（1.x→2.x） | 核心信念、人格、阻抗基线等重大变更，行为表现差异大 | 仅对新会话生效，进行中会话锁定原主版本，结束前不升级 |
| 次版本（1.1→1.2） | 新增算子、优化参数、补充细节，核心行为不变 | 进行中会话可平滑升级，无感知生效 |
| 修订号（1.1.0→1.1.1） | bug 修复、文案修正、规则微调 | 全量实时生效，所有会话同步更新 |

（2）版本迁移工具：提供手动迁移入口，用户可选择将会话迁移到最新主版本；迁移时系统自动兼容状态，基于新角色内核重新校准当前动态状态，避免跳变。

**架构融入位置**：数据服务层（角色资产域完善版本元数据，会话创建时绑定主版本号）；编排层（会话初始化时校验版本，按规则加载对应版本内核）。

**落地优先级**：Phase 2 UGC 体系上线时同步落地。

## 五、性能成本层面：长期膨胀管控

定位：解决长周期运行下的性能与成本膨胀问题，全部为内部机制优化，对外无感知。

### 5.1 长程记忆分层压缩机制

**现状缺口**：当前长时记忆按轮次存储，仅靠 TopN 召回与遗忘机制控制。几十上百轮的长程个案，记忆向量会持续膨胀，检索耗时与 Token 消耗稳步上涨，最终出现成本失控、延迟升高。

**风险影响**：长程会话越用越慢、越用越贵；用户量上来后，向量检索与模型成本指数级增长。

**详细落地方案**：

（1）三级记忆压缩体系：在原有三级记忆基础上，新增「摘要压缩层」，对长时记忆做分级聚合：

1. **轮次原始记忆**：单轮对话细节，保留 30 天内的完整内容；
2. **会话级摘要记忆**：单次会谈结束后，自动生成整轮会话的核心摘要，替代原始轮次细节；
3. **周期级摘要记忆**：每 5 次会谈生成一份周期摘要，压缩核心事实与关系变化，替代旧的会话摘要。

（2）召回策略：

- 优先召回近期原始记忆 + 远期摘要记忆；
- 越久远的记忆，颗粒度越粗，Token 占用越少；
- 核心事实、创伤点等高重要度记忆永久保留原始粒度，不压缩。

（3）异步执行：所有摘要压缩全部由后台异步任务执行，不占用同步对话链路的时间。

**架构融入位置**：核心引擎层 → 分层记忆引擎 → 新增「记忆摘要压缩子模块」；数据服务层（长时记忆表新增记忆等级字段，区分原始 / 摘要）。

**落地优先级**：Phase 2 落地基础压缩，Phase 3 长程场景完善。

### 5.2 算子数值边界管控体系

**现状缺口**：算子越多，同一轮叠加的调节系数越多，容易出现阻抗 > 1、情绪值溢出、置信度超出 0-1 范围的问题；算子叠加的边际效应无法控制，最终出现数值失控。

**风险影响**：BDI 输出异常，来访行为极端化；数值溢出导致逻辑 bug，调试困难。

**详细落地方案**：

（1）统一数值规范：

- 所有状态变量（阻抗、情绪、同盟、信念置信度）全部归一化到 [0, 1] 区间；
- 所有算子必须声明影响方向与最大影响幅度，注册时校验；
- BDI 输出前强制执行边界钳位，超出 0-1 范围的值自动修正到边界值。

（2）边际效应递减规则：

- 同一状态变量，同方向连续多次调节，效果边际递减；
- 例：连续 10 轮共情，阻抗不会一直降到 0，降到阈值后下降速度大幅放缓；
- 避免算子叠加导致数值极端化，符合真实心理规律。

（3）监控与回归：

- 所有算子的数值影响纳入自动化回归测试集，每次新增算子必须校验边界；
- 基础设施层监控异常数值，出现溢出立即告警。

**架构融入位置**：核心引擎层（BDI 引擎新增「边界校验组件」，算子注册机制补充范围声明）；基础设施层（监控指标新增异常数值告警）。

> 工程裁剪（母版）：基线与算子叠加后统一 clamp01 已在 WP1 落地；Phase1 只补算子幅度声明 + 边界回归断言，边际递减与溢出监控放 Phase2/3。

**落地优先级**：Phase 1 基础边界校验，Phase 2 完善边际效应与监控。

## 六、分阶段落地路线图

| 阶段 | 必须落地项 | 可选落地项 | 核心目标 |
|---|---|---|---|
| Phase 1 基础底座期 | 状态事务幂等、流式断连对齐、学员风险兜底、数值边界基础校验 | 轻度降级规则 | 核心链路稳定可靠，合规底线守住 |
| Phase 2 专业增强期 | 咨询同盟模型、间隔自然演化、降级状态回溯、UGC 运行时风控、数据分级留存、实训评估引擎、会话分支、角色版本兼容、记忆基础压缩 | 非语言互动基础版 | 专业真实感达标，生态能力成型 |
| Phase 3 生态完善期 | 非语言互动完善版、记忆分层压缩全量、算子边际效应全量 | 高阶评估标尺 | 长程体验极致，成本性能最优 |
| Phase 4 终局生态期 | 全量优化，数据驱动迭代 | — | 行业标准级底座 |

## 最终结论

这 14 项盲区补充，全部不破坏原五层架构的核心骨架与主流水线，只是在现有框架内做能力填充与机制完善。其中 3 项为 Phase1 上线必做的硬底线（状态幂等、断连对齐、学员风险），其余均可按业务节奏逐步落地，渐进式向终局态演进。
