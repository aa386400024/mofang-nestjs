## 方案定位

本方案为心塑 APP AI 来访仿真体系的终局技术总设计，不以 Demo 或 MVP 为目标，而是面向行业级实训基础设施的完整技术架构。方案深度融合当前学界前沿的心理仿真方法论、工业界成熟的 Agent 工程实践，将所有核验通过的开源资产进行体系化落地，彻底区别于市面通用的「大 Prompt 角色扮演」类产品，构建不可复制的专业技术护城河。

## 终局态核心目标

1. **专业能力终局**：实现临床级别的来访者认知仿真，阻抗、移情、防御、情绪演化完全符合心理咨询专业逻辑，可作为行业通用实训标准底座。
2. **架构能力终局**：支撑十万级并发实训会话、百万级角色资产、亿级会话数据沉淀，具备线性扩展能力。
3. **生态能力终局**：支持 UGC 资产共建、B 端机构白标、第三方 API 开放、多流派标准迭代，形成数据与生态正向复利。
4. **合规能力终局**：全链路符合心理行业监管要求，伦理风险全流程可控，所有行为可追溯、可审计。

## 核心设计原则

1. **内核与状态完全分离**：角色原生设定永久不可变，会话动态状态独立持久化，从架构层面杜绝人设漂移。
2. **认知决策与语言生成分离**：先通过结构化引擎完成心理决策，再交由大模型完成语言渲染，不将专业推理完全交给模型幻觉。
3. **开源资产最大化复用**：不重复造轮子，所有复用资产均经过活跃度与完整性核验，学界成熟方法论、工业界成熟组件全部体系化落地。
4. **全链路可观测可审计**：所有中间状态、决策过程、输出结果全量留痕，支持专业调试、效果评估、合规审计。
5. **渐进式演进可达**：终局架构可通过分阶段落地实现，每一阶段均具备业务价值，不存在架构推倒重建风险。

## 一、整体技术架构（终局态）

### 1.1 分层架构总览

终局架构采用五层企业级分层设计，各层职责边界清晰，向下依赖、向上服务，具备独立迭代与扩展能力。

| 架构层级 | 核心职责 | 核心模块 |
|---|---|---|
| 接入层 | 多端协议适配、流量治理、安全鉴权 | 流式会话网关、管理后台接口、B 端开放接口、UGC 资产接口、统一鉴权与限流 |
| 编排层 | 全链路业务流程编排、状态机管理、事件总线、熔断降级组件 | Agent 工作流引擎、会话状态机、事件总线 |
| 核心引擎层 | 来访者仿真核心能力，产品核心护城河 | BDI 认知仿真引擎、会话轨迹控制引擎、分层记忆引擎、伦理安全引擎、多模型语言渲染引擎 |
| 数据服务层 | 统一数据访问、存储适配、数据资产管理 | 关系型数据服务、向量检索服务、缓存服务、数据治理组件 |
| 基础设施层 | 底层资源支撑、运维治理、可观测体系 | 容器化调度、数据库集群、缓存集群、监控告警、日志链路 |

### 1.2 技术栈全景矩阵

| 技术领域 | 终局选型 | 选型说明 |
|---|---|---|
| 后端框架 | NestJS 10.x | 企业级 Node.js 框架，原生支持模块化、依赖注入、微服务扩展，匹配团队技术栈 |
| Agent 编排 | Mastra 企业级版 | 原生适配 NestJS，支持工作流编排、状态持久化、多模型管理、可观测体系，替代自研排层 |
| BDI 推理底座 | classic-agents 扩展定制 + PatientHub 临床模型注入 | TypeScript 原生 BDI 代理框架提供基础推理循环，基于心理咨询场景与临床标准深度定制 |
| 主数据库 | PostgreSQL 16 集群 | 支持 JSONB、事务、复杂查询，配套 pgvector 实现向量检索，无需独立部署向量数据库 |
| 向量检索 | pgvector 0.7.x | PostgreSQL 原生扩展，支持千亿级向量检索，与业务数据同库，降低架构复杂度 |
| 缓存中间件 | Redis 7.x 集群 | 热点数据缓存、会话状态缓存、分布式锁、限流削峰 |
| 消息队列 | RabbitMQ | 异步解耦、流量削峰、下游评分/档案/通知类异步任务调度 |
| 大模型主模型 | MiniMax M3.1-Flash | 高性价比、中文能力优秀、流式输出稳定，作为主推理与生成模型 |
| 大模型兜底模型 | DeepSeek-V3 / 通义千问极速版 | 多模型容灾，主模型故障时自动切换，保障服务可用性 |
| 安全护栏 | PsyGUARD 中文细粒度分类器 + MindGuard 临床级护栏 + 自研规则引擎 | 三层防护架构，覆盖中文专项危机检测、临床级通用护栏、硬规则兜底 |
| 可观测体系 | Prometheus + Grafana + OpenTelemetry | 全链路指标、监控、追踪一体化 |
| 部署架构 | Kubernetes + Docker | 容器化编排，支持水平弹性伸缩、灰度发布、故障自愈 |

### 1.3 模块全景交互关系

接入层接收前端会话请求后，统一交由编排层调度；编排层按照预设工作流依次调用核心引擎层各模块，完成从事件感知、认知决策、记忆召回、伦理校验到语言生成的全流程；所有数据操作通过数据服务层统一访问，保证数据一致性与治理能力；全链路通过基础设施层实现监控、日志、追踪。

## 二、开源资产深度复用体系

> 本章所有资产均经过真实仓库状态核验，剔除空壳仓库与长期停更项目，每一项均对应明确的架构落点与业务价值。

### 2.1 领域专业类资产（构建专业护城河）

#### 2.1.1 PatientHub（含 PATIENTACT 临床级患者行为仿真框架）
- **落地位置**：角色内核数据模型标准 + BDI 认知引擎临床行为逻辑 + 阻抗量化体系 + 角色质量评估体系。
- **复用核心能力**：
  - a. 5Ps 临床个案概念化模型（主诉、易感因素、诱发因素、维持因素、保护因素），作为角色内核的专业标准；
  - b. 三维度阻抗模型（话量阻抗、内容深度阻抗、表达风格阻抗），实现阻抗的可量化、可计算；
  - c. 标准化个案生成脚本，支持批量生成符合临床逻辑的来访者角色资产；
  - d. 临床合理性评估体系，用于 UGC 角色入库的专业质量校验。
- **核验状态**：EMNLP 2026 收录，2026 年 8 月仍有代码更新，工程化完整，CLI 工具可直接调用。
- **业务价值**：将来访角色专业度从「体感层面」升级为可量化临床标准，大幅拉开与普通竞品的专业差距，支撑多流派评分体系的底层数据一致性，替代原 V1.1 中空壳资产的专业标准定位。

#### 2.1.2 AnnaAgent（长程心理咨询对话 Agent）
- **落地位置**：分层记忆引擎核心架构 + 情绪演化机制 + 跨会话接续方案。
- **复用核心能力**：
  - a. 三级记忆架构（工作记忆、短时记忆、长时记忆），匹配人类记忆规律；
  - b. 情绪状态流转模型：情绪随咨询过程动态变化，具备累积、衰减、转移特性；
  - c. 长程会话接续方案：跨会话恢复时自动承接情绪、议题、关系状态；
  - d. 咨询阶段划分标准，支撑会话轨迹的阶段化管控。
- **核验状态**：ACL 2025 收录，2026 年 6 月核心包更新，PyPI 发布正式版本 0.3.1。
- **业务价值**：完美支撑长程个案实训场景，让多次会谈具备真实的连续性与成长感，符合真实咨询的过程规律，为长程实训提供成熟的记忆与情绪方法论。

#### 2.1.3 PsycheChat（心理健康对话系统，含 Seeker 来访模型）
- **落地位置**：多模型语言渲染引擎中 文风格优化 + 情绪状态校验补充 + 初始对话场景素材库。
- **复用核心能力**：
  - a. 中文来访者对话风格模型（Seeker），贴合国内来访者的表达习惯与心理特征；
  - b. 多维度情绪标签体系，补充 BDI 引擎的情绪粒度；
  - c. 基础对话边界识别逻辑，辅助判断咨询师越界行为；
  - d. 标准化中文心理咨询对话数据集，用于初始轨迹剧本提炼。
- **核验状态**：EMNLP 2026 Main 收录，2026 年 8 月代码更新，完整开源模型与推理代码。
- **业务价值**：提升中文来访对话的真实感与沉浸感，丰富伦理检测维度，降低误判率，并为初始资产建设提供高质量中文对话素材。

#### 2.1.4 PsyGUARD（中心理咨询自杀风险检测框架）
- **落地位置**：伦理安全引擎中文专项检测层 + 危机场景识别核心。
- **复用核心能力**：
  - a. 11 类细粒度心理风险分类（自杀行动、自杀意念、自伤、攻击行为、受虐等），精准区分创伤倾诉与高危意图；
  - b. 配套 PsySUICIDE 中文数据集（15010 条专家标注样本），覆盖多场景中文心理对话；
  - c. RoBERTa 与大模型双版本实现，轻量版可 CPU 部署，满足实时检测需求；
  - d. 风险分级机制，匹配不同等级的处置策略。
- **核验状态**：EMNLP 2024 Main 收录，代码、模型、数据集全开源，持续迭代优化。
- **业务价值**：填补中文场景下心理咨询专项危机检测的空白，大幅提高高危内容识别精准度，既保障平台合规底线，又避免过度拦截影响实训体验。

#### 2.1.5 LifeSim（长周期用户生命仿真框架）
- **落地位置**：BDI 认知仿真引擎理论参考 + 事件驱动机制设计借鉴。
- **复用核心能力**：
  - a. BDI（信念-愿望-意图）认知模型的分层设计思路，区分静态人格与动态心理状态；
  - b. 事件-信念交互逻辑：外部事件触发内部信念更新，进而驱动行为变化；
  - c. 长周期状态演化的设计理念，适配长程个案的心理连续性。
- **核验状态**：学术原型项目，无成熟工程化接口，不直接复用代码。
- **业务价值**：为 BDI 引擎的顶层设计提供学界方法论参考，从架构层面保障认知模型的专业性，核心工程实现基于 classic-agents 落地。

- **落地位置**：BDI 认知仿真引擎工程底座。
- **复用核心能力**：
  - a. 原生 BDI 代理推理循环：信念更新、愿望排序、意图生成、计划执行完整闭环；

- **业务价值**：避免从零实现 BDI 推理循环，大幅降低核心引擎开发成本与风险，保证推理逻辑的工程严谨性。

- **落地位置**：全链路编排层核心底座。

  - a. NestJS 原生适配，无缝融入现有技术栈；
  - b. 可视化工作流编排，支持分支、循环、重试、降级等复杂流程；

#### 2.2.3 MindGuard（临床级心理健康安全护栏）

  - b. 支持情绪分类、风险识别、语义匹配等多任务微调；

- **业务价值**：提升长时记忆语义检索的精准度，优化情绪识别的细粒度，同时降低核心场景的大模型调用成本。

## 三、核心引擎层详细设计（终局态）

核心引擎层是产品的技术核心与专业护城河，五大引擎协同工作，完整实现来访者认知仿真全能力。

### 3.1 BDI 认知仿真引擎

**引擎定位**：来访仿真的核心决策大脑，负责模拟来访者的内部心理活动，输出结构化的行为目标，是「先决策后生成」设计原则的核心载体。

**三层认知模型**：

1. **信念层（Belief）**
   - 核心信念：源自角色内核（基于 PatientHub 5Ps 模型定义），永久不可变，对应原生家庭、人格底层认知；
   - 短期信念：会话过程中动态形成，可被咨询师干预影响，具备置信度属性；
   - 记忆信念：从长时记忆中召回的历史认知，具备时效性。
2. **愿望层（Desire）**
   - 底层愿望：被理解、被接纳、回避痛苦、寻求掌控感等人类底层心理诉求；
   - 情境愿望：当前会话场景下的具体诉求，如「回避谈论父亲」「想要得到肯定」；
   - 所有愿望具备权重与优先级，随信念变化动态调整。
3. **意图层（Intention）**
   - 本轮会话的具体行为目标，是信念与愿望共同作用的输出结果；
   - 包含：行为策略、情绪状态、阻抗等级、移情等级、禁止行为五大结构化字段。

**事件驱动的状态演化机制**：借鉴 LifeSim 事件-信念交互设计理念，基于 classic-agents 的事件调度机制实现：将会话中的咨询师行为、场景变化抽象为标准会话事件，每个事件对应明确的信念/愿望影响算子：

- 正向事件（共情、接纳、正常化）：降低阻抗、提升信任、提升开放度；
- 负向事件（评判、说教、打断、越界）：提升阻抗、触发防御、降低开放度；
- 触发事件（触碰创伤点、提及敏感议题）：触发情绪波动、防御机制激活。

事件算子采用「硬规则 + 大模型微调」双轨实现，高频场景规则兜底，复杂场景模型推理。

**阻抗与移情量化体系**：复用 PatientHub 三维阻抗模型，实现阻抗的可量化计算：

- 话量阻抗：控制回复长度，阻抗越高回复越简短；
- 内容深度阻抗：控制自我暴露程度，阻抗越高越回避深层议题；
- 表达风格阻抗：控制语气与态度，阻抗越高越疏离、对抗。

移情维度独立量化，分为正移情、负移情、依赖移情三大类，随咨询关系动态变化，直接影响行为意图生成。

### 3.2 会话轨迹控制引擎

**引擎定位**：针对标准化实训场景的强可控仿真引擎，保证特定训练场景的可复现性，是伦理盲盒、专项训练包、标准化考核的核心支撑。

**轨迹定义标准**：基于 PatientHub 临床个案进程节点标准与 AnnaAgent 会话阶段划分方法，构建标准化轨迹范式，每条轨迹剧本包含：

1. 基础元数据：适配角色、适用场景、难度等级、训练目标；
2. 节点序列：按顺序或触发条件排列的行为节点，每个节点包含触发条件、行为目标、参考素材、状态偏移量；
3. 退出机制：节点完成判定、异常分支处理、轨迹结束条件。

初始轨迹素材基于 PsycheChat 公开心理咨询对话场景提炼，覆盖主流咨询议题与伦理场景。

**三种运行模式**：

1. **强覆盖模式**：预设行为目标完全覆盖 BDI 引擎输出，来访行为严格按照剧本执行，用于标准化考核、核心伦理场景；
2. **修正模式**：预设目标对 BDI 输出进行加权修正，在保证主线不偏离的前提下保留一定灵活性，用于专项训练包；
3. **触发模式**：正常状态下 BDI 自由运行，满足特定触发条件时激活对应轨迹节点，用于隐藏式伦理坑、突发危机场景。

**伦理盲盒专项实现**：所有高危伦理场景均采用强覆盖模式轨迹，确保每次演练的触发点、行为表现、风险点完全一致，实训效果可衡量。内置来访表白、索要私人联系方式、熟人咨询、录音纠纷、诊断证明诉求、自杀危机等全量伦理与危机场景。

### 3.3 分层记忆引擎

**引擎定位**：管理来访者的全生命周期记忆，保障会话连续性与角色一致性，是长程个案的核心支撑。

**三级记忆架构**：复用 AnnaAgent 三级记忆体系，结合 pgvector 向量检索，借鉴竞争抑制遗忘逻辑自研优化：

- **工作记忆**：当前回合的上下文信息，直接参与本轮决策，容量为最近 8 轮对话；
- **短时记忆**：单会话内的完整对话摘要，伴随会话全程，会话结束后转为长时记忆；
- **长时记忆**：跨会话的核心事实、情绪体验、关系变化，永久存储于向量库。

语义检索基于 Chinese-MentalBERT 生成向量，提升心理场景下的记忆召回精准度。

**记忆管理机制**：

1. 写入机制：每轮会话结束后自动生成记忆摘要，计算向量后存入长时记忆库；
2. 检索机制：新回合开始时，基于当前议题语义检索 Top5 相关记忆，过滤过期与冲突内容；
3. 遗忘机制：采用竞争抑制逻辑，记忆重要度随时间衰减，低重要度记忆不再被召回，符合真实记忆规律；
4. 冲突消解：出现记忆冲突时，以时间更近、置信度更高的记忆为准，同时记录冲突点。

**跨会话接续方案**：长程会话恢复时自动加载：

- 上一会话结束时的 BDI 状态（情绪、阻抗、移情）；
- 核心议题进度与未完成事项；
- 咨询关系状态；
- 高权重长时记忆。

基于上述信息生成本次会话开场白，实现无缝接续。

### 3.4 伦理安全引擎

**引擎定位**：全链路合规防护体系，贯穿会话前、会话中、会话后全流程，是产品合规红线的技术保障。

**三层检测架构**：

1. **规则检测层**：基于关键词、正则、语义模板的硬规则检测，毫秒级响应，覆盖明确的越界行为。
   - 禁止行为：给人生建议、承诺治愈、价值审判、双重关系引导等；
   - 高危内容：自杀自残指导、违法建议、歧视性言论等。
2. **中文专项检测层**：基于 PsyGUARD-RoBERTa 实现，针对中文心理咨询场景优化，识别细粒度风险。
   - 11 类心理风险精准分类，区分创伤倾诉与真实高危意图；
   - 轻量模型 CPU 部署，延迟 <50ms，满足实时检测需求。
3. **临床级通用检测层**：基于 MindGuard 实现，作为高阶兜底与输出侧护栏。
   - 隐性越界：变相指导、过度自我暴露、操纵性语言等；
   - 高危风险：真实自杀意图、自伤计划等极端风险；
   - 同时对 AI 来访的输出内容进行校验，避免生成违规引导内容。

**全链路防护机制**：

- 会话前：角色资产审核，确保来访人设不包含违规引导内容；
- 会话中：实时检测咨询师输入与来访输出，中低风险告警、高风险拦截；
- 会话后：全量对话复盘审计，生成伦理风险报告，纳入实训档案。

### 3.5 多模型语言渲染引擎

**引擎定位**：将结构化行为目标转化为自然口语化对话输出，是大模型能力的唯一出口，同时负责成本管控与容灾降级。

**模型分层调度策略**：基于任务类型选择最优模型，兼顾效果与成本：

1. 结构化推理任务（BDI 状态更新、意图生成、记忆摘要）：使用 MiniMax M3.1-Flash，低温参数，短上下文，保证输出稳定可控；
2. 对话生成任务：使用 MiniMax M3.1-Flash，高温参数，流式输出，结合 PsycheChat 来访风格 Prompt 优化，保证中文口语化与沉浸感；
3. 复杂专业任务（伦理深度检测、质量评估）：使用高阶模型，按需调用，控制成本。

**核心机制**：

1. 约束注入机制：将行为目标、人设约束、伦理要求结构化注入 Prompt，确保生成内容不偏离决策结果；
2. 流式输出适配：支持 SSE 与 WebSocket 双协议，匹配前端语音流式播放需求；
3. 多模型容灾：主模型异常时自动切换备用模型，故障恢复后自动切回，业务无感；
4. Token 预算管控：单轮对话设置 Token 上限，记忆片段与对话历史动态裁剪，避免成本失控。

## 四、数据架构设计

### 4.1 数据域划分

终局态数据体系分为四大数据域，各域边界清晰，职责明确。

| 数据域 | 核心内容 | 存储载体 |
|---|---|---|
| 角色资产域 | 角色内核、轨迹剧本、版本信息、审核记录 | PostgreSQL |
| 会话状态域 | BDI 状态、记忆数据、轨迹进度、会话元信息 | PostgreSQL + pgvector + Redis |
| 业务流水域 | 会话记录、轮次明细、审计日志、操作流水 | PostgreSQL + 归档存储 |
| 生态运营域 | UGC 资产、评分数据、受训档案、B 端机构数据 | PostgreSQL |

### 4.2 核心数据模型设计

#### 4.2.1 角色内核模型
基于 PatientHub 5Ps 临床模型构建，是所有仿真的基础，具备版本管理与审核机制，支持 UGC 共建。核心维度：

- 基础属性：姓名、年龄、性别、人口学信息；
- 5Ps 个案模型：主诉、易感因素、诱发因素、维持因素、保护因素；
- 人格与沟通：人格特质、沟通风格、阻抗基线；
- 专业标签：适配流派、适配议题、难度等级；
- 版本管理：版本号、变更记录、审核状态、创作者信息。

#### 4.2.2 会话状态模型
每一个案会话独立一份状态，与会话生命周期绑定，支持暂停、恢复、归档。核心维度：

- 会话基础信息：关联角色、用户 ID、开始时间、当前状态；
- BDI 状态快照：当前信念集合、愿望权重、当前意图；
- 轨迹进度：当前节点、触发历史、分支记录；
- 统计指标：已进行轮次、累计时长、阻抗均值、移情变化曲线。

#### 4.2.3 记忆数据模型

- 短时记忆：与会话绑定，结构化存储对话摘要；
- 长时记忆：与角色 + 用户绑定，包含向量、内容、重要度、时间戳、来源标签。

### 4.3 存储体系设计

1. 关系型存储：PostgreSQL 一主多从集群，承载核心业务数据，按业务域分库分表，支撑亿级数据量；
2. 向量存储：pgvector 与业务库同集群，长时记忆表单单独分区，建立向量索引；
3. 缓存存储：Redis 集群，承载热点角色数据、活跃会话状态、分布式锁、限流计数；
4. 归档存储：冷数据、历史会话、审计日志定期归档至对象存储，降低存储成本；
5. 消息存储：RabbitMQ 承载异步任务解耦，支持下游评分、档案、通知等异步消费。

### 4.4 数据治理体系

1. 数据标准：所有字段、枚举、标签统一标准，保证跨模块数据一致性；
2. 质量校验：角色资产入库、UGC 提交、状态更新均设置质量校验规则，不合格数据无法入库；
3. 版本管理：角色、轨迹、评分标尺均支持多版本管理，历史版本可回溯、可重评；
4. 隐私脱敏：所有用户数据、对话内容均做脱敏处理，UGC 资产强制脱敏审核；
5. 数据安全：敏感数据加密存储、访问权限分级、操作全量审计。

## 五、核心业务场景实现方案

### 5.1 长程个案实训场景

1. 用户选择长程来访角色，创建个案会话；
2. 系统初始化角色内核、BDI 初始状态、空白记忆库；
3. 每轮会谈按「事件感知 → BDI 推理 → 记忆召回 → 伦理校验 → 语言生成 → 状态更新」流程执行；
4. 会谈结束后，状态全量持久化，记忆摘要写入长时记忆库；
5. 下次进入同一个个案时，自动加载最新状态与核心记忆，无缝接续会谈；
6. 全程自动生成受训档案与能力成长曲线。

### 5.2 伦理盲盒专项实训场景

1. 用户选择伦理训练主题，系统加载对应轨迹剧本与匹配角色；
2. 初始阶段 BDI 自由运行，模拟正常咨询过程；
3. 当咨询师行为满足触发条件时，轨迹引擎自动激活对应节点，强制触发伦理事件；
4. 全程三层伦理检测实时运行，同步标注用户应对中的合规与违规点；
5. 会谈结束后生成专项伦理复盘报告，纳入伦理实训档案。

### 5.3 UGC 资产共建场景

1. 督导/成熟咨询师提交角色人设或轨迹剧本；
2. 系统自动进行格式校验、合规校验、专业质量初评（基于 PatientHub 临床评估体系）；
3. 平台专业审核委员会进行人工盲审，投票决定是否入库；
4. 审核通过的资产分配唯一标识与版本号，正式纳入资产池；
5. 资产被使用时自动统计调用量，按规则为创作者结算分成与权益。

### 5.4 督导批量管理场景

1. 督导创建班级，批量导入学员；
2. 督导通过 B 端工作台下发实训任务，指定角色、轨迹、训练目标；
3. 系统自动跟踪全班学员实训进度，生成班级能力看板与薄弱项统计；
4. 督导可批量查看学员会谈记录、BDI 状态、伦理报错，批量批注与复盘；
5. 所有实训数据自动同步至学员个人受训档案。

### 5.5 机构白标授权场景

1. 机构申请白标授权，系统生成独立租户空间；
2. 机构可自定义品牌标识、自有角色资产、专属评分标尺；
3. 机构学员数据独立存储，与平台主数据隔离；
4. 平台提供底层仿真能力、合规能力、档案能力，机构专注教学运营；
5. 按授权年费 + 使用量结算费用。

## 七、非功能设计（企业级）

### 7.1 性能与扩展性

- 并发能力：单集群支持 10 万级同时在线会话，单轮对话端到端延迟 <500ms（首字）；
- 水平扩展：所有无状态服务支持水平扩容，数据库支持读写分离、分库分表；
- 流量削峰：通过消息队列异步处理非实时任务，大模型调用批量排队，避免峰值冲击；
- 资源隔离：C 端实训、B 端管理、开放 API 资源隔离，避免业务互相影响。

### 7.2 高可用与容灾

- 服务可用性：核心服务 SLA 99.9%，年度 downtime <8.76 小时；
- 多活容灾：核心数据库主从切换、异地备份，RPO <5 分钟，RTO <30 分钟；
- 降级机制：核心引擎异常时，自动降级为基础 Prompt 模式，保证对话可用；非核心功能一键降级；伦理检测降级为规则兜底；
- 故障自愈：K8s 自动重启异常实例，自动扩容应对流量上涨，故障自动告警。

### 7.3 可观测体系

1. 指标监控：覆盖业务指标（在线会话数、角色调用量）、性能指标（接口耗时、模型响应耗时）、成本指标（Token 消耗、单会话成本）、合规指标（风险拦截量、误报率）；
2. 全链路追踪：OpenTelemetry 埋点，单轮会话全链路可追溯，支持问题快速定位；
3. 日志体系：结构化日志全量采集，支持按 TraceId、会话 Id、角色 Id 多维度检索；
4. 专业可观测：支持角色效果观测，可回放单会话完整 BDI 状态变化、决策过程，便于专业调试与优化。

### 7.4 成本管控体系

1. 模型分层调用：不同任务匹配不同规格模型，避免大模型小用；伦理前置检测采用轻量开源模型，大幅降低大模型调用成本；
2. 上下文裁剪：记忆检索、对话历史动态裁剪，严格控制单轮 Token 量；
3. 缓存复用：热点角色、通用意图、重复场景结果缓存复用，减少模型调用；
4. 成本看板：实时监控整体与单用户成本，设置成本预警，异常消耗自动限流；
5. 用量优化：长会话自动摘要替换完整历史，低频记忆自动归档，降低存储与计算成本。

### 7.5 安全与合规

1. 数据安全：敏感数据加密存储，传输全程 HTTPS，数据备份加密；
2. 内容合规：全链路三层内容审核，输入输出双重校验，违规内容实时拦截；
3. 隐私保护：严格遵守个人信息保护法，用户对话数据仅用于实训，不用于模型训练，支持数据删除；
4. 权限体系：RBAC 分级权限，用户、督导、管理员、机构多角色权限隔离；
5. 审计留痕：所有操作全量审计日志，永久留存，支持合规追溯。

## 八、分阶段演进路线

终局架构采用四阶段渐进式落地，每一阶段均具备完整业务价值，逐步向终局演进。

### Phase 1：基础底座期（0-4 个月，对应产品第一阶段）

**核心目标**：跑通双模式核心链路，上线基础实训能力，验证核心架构可行性。

**落地能力**：

1. 简化版 BDI 认知引擎：基于 classic-agents 扩展，实现基础信念-愿望-意图推理，注入 PatientHub 5Ps 角色内核标准；
2. 会话轨迹控制引擎 V1：支持强覆盖模式，落地 10 个核心伦理盲盒剧本（基于 PsycheChat 公开场景提炼）；
3. 二级记忆引擎（工作记忆 + 短时记忆），基础 pgvector 向量检索能力；
4. 规则层 + PsyGUARD 轻量版双层伦理安全引擎，覆盖核心伦理红线与基础危机识别；
5. MiniMax 主模型对接，流式输出能力，基础中文风格优化；
6. 基础角色资产池：基于 PatientHub 生成初始人设 + 公开中文心理对话数据集提炼扩充；
7. 基础可观测与运维体系。

**业务价值**：支撑产品上线内测，核心对练功能可用，伦理场景具备基础能力。

### Phase 2：专业增强期（5-12 个月，对应产品第二阶段）

**核心目标**：补齐专业能力，拉开与竞品差距，支撑规模化用户增长。

**落地能力**：

1. BDI 引擎精细化：完善事件算子库，落地 PatientHub 完整三维阻抗模型与移情量化体系；
2. 记忆引擎升级：落地三级记忆架构，引入竞争抑制遗忘机制，完善长程接续能力；
3. 伦理引擎升级：接入 MindGuard 临床护栏，形成「规则 + 中文专项 + 临床级」三层检测架构；
4. UGC 共建体系完整落地：提交-审核-入库-分成全流程，配套 PatientHub 临床质量校验；
5. B 端督导工作台基础版：班级管理、批量任务、能力看板；
6. 完整的成长档案体系；
7. 性能优化，支撑万级并发。

**业务价值**：专业能力全面超越竞品，支撑 C 端会员与 B 端基础付费，形成稳定营收底盘。

### Phase 3：生态完善期（13-24 个月，对应产品第三阶段前期）

**核心目标**：完善生态能力，强化护城河，构建数据复利。

**落地能力**：

1. BDI 引擎深度优化：基于真实实训数据迭代事件算子与行为模型，提升仿真精准度；
2. 流派差异化参数体系：不同流派来访反应逻辑差异化，匹配专业评分标尺；
3. 机构白标授权体系完整落地；
4. AI 自适应成长引擎：基于用户实训数据自动推送定制化训练包；
5. 完整的角色质量评估体系，基于 PatientHub 临床标准；
6. 数据资产沉淀：形成行业匿名实训数据集，持续优化风险检测与仿真模型。

**业务价值**：生态闭环形成，B 端营收占比提升，数据复利效应显现，行业话语权建立。

### Phase 4：终局生态期（24 个月+，对应产品第三阶段终局）

**核心目标**：成为行业实训基础设施，构建终局生态。

**落地能力**：

1. 流派标尺评审委员会线上化体系，支持多督导联合迭代标准；
2. 开放 API 平台，对外输出来访仿真、伦理检测、评分等核心能力；
3. 行业数据报告体系，定期发布行业实训数据洞察；
4. 多模型混合调度体系，根据场景智能选择最优模型；
5. 全链路智能化调优，成本与效果自动平衡。

**业务价值**：成为行业标准底座，生态收益成为重要营收组成，构建无法被超越的终局护城河。

## 九、风险与治理

| 风险类型 | 具体风险 | 影响等级 | 应对措施 |
|---|---|---|---|
| 专业风险 | 来访仿真不符合专业逻辑，实训价值不足 | 高 | 1. 核心模型基于 PatientHub、AnnaAgent 等顶会成熟框架，不凭空自研；2. 建立专业审核委员会，所有角色与规则经专业校验；3. 持续基于真实督导反馈迭代优化 |
| 技术风险 | BDI 引擎人设漂移，行为偏离预期 | 中高 | 1. 架构层面内核与状态分离，核心信念基于 5Ps 标准永久不可篡改；2. 行为输出前置校验，偏离目标自动重生成；3. 完善降级机制，异常时切换稳定模式 |
| 成本风险 | 用户量增长后，大模型调用成本失控 | 中 | 1. 全链路 Token 管控，严格控制上下文长度；2. 模型分层调度，非核心场景用轻量开源模型；3. 缓存复用机制，减少重复计算；4. 成本实时监控，异常自动预警限流 |
| 合规风险 | 对话内容违规，引发监管风险 | 极高 | 1. 全链路三层伦理检测，高风险实时拦截；2. 全量对话留痕审计，定期合规巡检；3. 严格恪守产品边界，不触碰执业红线；4. 定期基于最新监管要求更新检测规则与模型 |
| 进度风险 | 引擎复杂度高，开发进度滞后 | 中 | 1. 分阶段落地，每一阶段均具备业务价值；2. 最大化复用经核验的活跃开源资产，减少自研工作量；3. 核心模块优先落地，非核心模块后置 |
| 生态风险 | UGC 资产质量参差不齐，影响平台专业度 | 中 | 1. 严格的审核机制，专业委员会盲审，配套临床质量初筛；2. 资产质量评分体系，优质资产加权曝光；3. 创作者分级制度，高信用创作者审核绿色通道 |
