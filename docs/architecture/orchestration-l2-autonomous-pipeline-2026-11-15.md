# L2 自治流水线落地设计（编排工具链 + 可视化）

> 日期：2026-11-15　拟稿：主控 AI（Doubao）
> 文档性质：**本仓 L2 承载落地设计**。框架规范件见框架仓 v1.3.0（`docs/autonomous-loop.md`、`schemas/agent-card.schema.json`）；本备忘只定义本仓工具链模块、数据模型、状态机衔接、围栏与网页结构，不改动业务代码。
> 与既有文档关系：`docs/architecture/multi-agent-collaboration-loop-design-2026-11-15.md` 是远期目标态参考架构论证留档，本备忘不修改它；本备忘是当前阶段 L2 承载的成型实现方案。

## 1. 背景与定位

框架仓已成型规范件：工具契约（`tools.md` + `tool-contract.schema.json`）、自治循环（`autonomous-loop.md`）、能力声明（`agent-card.schema.json`）。本仓当前执行承载仍是 L0：文件 + 轻量索引 + 平台 cron 轮询回执。本设计把自治循环的**编排状态机、机读验收护栏、返修闭环、交付包汇总**落地为本仓工具链，并提供只读可视化网页；执行代理（MiniMax Code）的桌面唤起通道边界见 §9。

**范围边界：**

- 做：队列扫描与领单租约、超时释放、回执验收驱动、返修拆单与限次、死信隔离、队列快照、夜间交付包、可视化网页、CLI 入口；
- 不做：不改 `src/` / `test/` / `bin/` 业务代码；不进框架仓运行时；不实现协议适配器 / 客户端 / 服务端 / 协议栈依赖（L3，AF-008）；不引入新的第三方 npm 依赖。

## 2. 总体架构

```
docs/team/agent-orchestration/task-state-index.json   # L0 既有索引（契约不变，只存指针与状态）
        ▲ 读写（只读既有契约字段，附加运行态落到独立 L2 状态文件）
        │
scripts/orchestration/
  config.json            # 自治开关、返修限次、围栏动作、任务类型白名单、租约默认时长
  state-store.mjs        # 状态持久化：读索引 + 附加 L2 运行态；原子写；租约字段
  acceptance-runner.mjs  # V1–V6 机读护栏；输出 verdict + manualReview 列表
  scheduler.mjs          # 一轮循环：扫队列 → 领单 → 回执验收 → 归档/返修/死信 → 快照
  delivery-pack.mjs      # 夜间交付包汇总（结论、证据指针、死信、遗留、待批动作）
  cli.mjs                # pnpm script 入口：status / run-once / pack / snapshot / config
        │
web/orchestration/  index.html · app.js · styles.css   # 静态只读可视化（读快照 JSON）
```

数据流向：CLI 读取索引与 L2 状态 → scheduler 驱动状态迁移并回写 → acceptance-runner 出验收结论 → delivery-pack 汇总 → 快照 JSON 供网页读取。

## 3. 模块职责

| 模块                    | 职责                                                                                       | 不做                                    |
| ----------------------- | ------------------------------------------------------------------------------------------ | --------------------------------------- |
| `config.json`           | 自治模式开关、返修上限（默认 2）、围栏动作类别、允许自动执行的任务类型白名单、租约默认时长 | 不存任务运行态                          |
| `state-store.mjs`       | 加载 / 保存索引与 L2 运行态；原子写（临时文件 + 替换）；租约读取与释放；按 taskId 查任务   | 不解析业务语义；不改既有索引字段语义    |
| `acceptance-runner.mjs` | 机读护栏 V1–V6；汇总机读结论；列出需人工复核项                                             | 不做契约语义 / 口径 SSOT / 分歧仲裁判定 |
| `scheduler.mjs`         | 队列扫描、依赖解锁判定、领单租约、超时释放、回执验收驱动、返修拆单、死信隔离、生成队列快照 | 不直接唤起桌面 GUI；不执行业务实现      |
| `delivery-pack.mjs`     | 汇总循环结论、证据指针、死信清单、遗留项、待批动作，生成交付包工件                         | 不复制工件正文                          |
| `cli.mjs`               | 命令行入口与参数解析；串联上述模块；输出人类可读摘要                                       | 不承担业务逻辑                          |

## 4. 数据模型

### 4.1 既有索引（契约不变）

`task-state-index.json` 既有字段（`version` / `schemaRef` / `tasks[]` / `archivedTasks[]`）保持不变；工具链只读取，不重排既有字段。

### 4.2 L2 运行态（独立附加文件，不污染既有索引）

`docs/team/agent-orchestration/orchestration-state.json`（运行态，纳入版本控制以便崩溃恢复）：

| 字段                           | 说明                                  |
| ------------------------------ | ------------------------------------- |
| `updatedAt`                    | 最近一次写盘时间（ISO）               |
| `tasks[taskId].attemptCount`   | 已返修 / 重试次数                     |
| `tasks[taskId].leaseClaimedAt` | 领取时间（ISO）                       |
| `tasks[taskId].leaseDeadline`  | 租约到期点（ISO）                     |
| `tasks[taskId].lastRunner`     | 最近领取 / 推进的执行方标识           |
| `tasks[taskId].reworkOf`       | 返修任务指向的被拒任务 taskId         |
| `tasks[taskId].frozen`         | 是否命中围栏动作、转 `input-required` |
| `tasks[taskId].autoVerdict`    | 最近一次机读验收结论与明细            |

### 4.3 配置（`config.json`）

| 字段                  | 默认                                   | 说明                                                                      |
| --------------------- | -------------------------------------- | ------------------------------------------------------------------------- |
| `autoLoop.enabled`    | `false`                                | 自治模式总开关；默认关闭，显式开启                                        |
| `reworkLimit`         | `2`                                    | 同一任务返修次数上限，超限进死信                                          |
| `leaseDefaultMinutes` | `30`                                   | 未声明 deadline 时的默认租约时长                                          |
| `allowedTaskTypes`    | `[implementation, fix, documentation]` | 允许自动执行的任务类型；`investigation` / `review` 只读产出，不自动改实现 |
| `frozenActions`       | 见 §7                                  | 命中即冻结、转 `input-required` 的动作类别                                |

## 5. 状态机衔接

九态枚举与有效迁移沿用框架 `docs/state-machine.md` §4；工具链不新增状态。循环阶段与状态映射：

| 循环阶段 | 状态迁移                                                         | 留痕                               |
| -------- | ---------------------------------------------------------------- | ---------------------------------- |
| 队列扫描 | —                                                                | —                                  |
| 领单     | `ready` → `submitted`                                            | `claimedAt`、领取者、租约到期点    |
| 等待回执 | `submitted`（开工后 `working`）                                  | —                                  |
| 验收通过 | → `completed`                                                    | 归档指针、索引回写                 |
| 验收打回 | 被拒任务 → `rejected`；返修新任务 → `ready`                      | 返修任务 `priorTasks` 指向被拒任务 |
| 死信     | → `input-required`（隔离）                                       | 错误上下文、已尝试路径、建议决策点 |
| 超时释放 | `submitted` / `working` 租约过期 → `ready`（可重派）或按失败定性 | 释放原因写入 `history`             |

终态（`completed` / `failed` / `canceled` / `rejected`）不可变；返修在同一 `contextId` 下新开任务。

## 6. 验收护栏（机读项与人工项分界）

对齐框架 `docs/tools.md` §8 V1–V6 与 `docs/acceptance.md` §3：

| 护栏          | 机读判定                                                | 分界     |
| ------------- | ------------------------------------------------------- | -------- |
| V1 任务单契约 | 必填字段齐全、字段组符合任务单 schema                   | 可脚本化 |
| V2 索引契约   | 索引结构、归档轻量指针、版本模式符合索引 schema         | 可脚本化 |
| V3 工件指针   | 登记指针存在且非空，可反查交付记录                      | 可脚本化 |
| V4 链接可达   | 文档相对链接目标存在；断链归零或显式标注                | 可脚本化 |
| V5 编码一致   | 文本工件无 BOM、CR=0、换行与约定一致                    | 可脚本化 |
| V6 工具契约   | 工具声明符合工具契约 schema（本仓当前无工具声明时跳过） | 可脚本化 |

机读全绿且无未决人工项 → `passed`；机读绿但存在遗留 / 人工复核项 → `conditional-pass`；机读缺口 → `rejected`。契约语义对齐、口径 SSOT、偏差合理性、分歧仲裁列入 `manualReviewList`，不由脚本下结论。

## 7. 围栏与冻结动作

自治模式下以下动作冻结，任务转 `input-required`，不阻塞队列其他任务：

- 对外发布：`git push`、对外系统写入、不可逆发布；
- 策略例外：触及红线或边界规则；
- 路线选型：多方案且代价不同；
- 跨任务变更：影响其他任务契约或切片；
- 验收分歧；
- 依赖变更：新增未声明依赖、引入新工具链。

冻结任务在交付包「待批动作」节列出，附任务标识与建议决策点（框架 `docs/human-in-the-loop.md` §4 标准字段）。

## 8. 返修、死信与熔断预留

- 返修：被拒任务终态不可变；返修任务同 `contextId`、`priorTasks` 指向被拒任务；`attemptCount` 累计；
- 限次：达 `reworkLimit`（默认 2）仍未通过 → 死信隔离，不再自动重试；
- 死信记录：任务标识、失败证据、已尝试路径、工件指针、建议人工决策点；
- 熔断：预留位；某工具 / 下游连续失败达阈值后暂停调用并升级为可观察事件（阈值由适配层声明，本版本不实现自动熔断计数）。

## 9. 桌面派发通道边界（现实约束）

工具链脚本本身**不直接控制桌面 GUI**。派发与回执衔接分两层：

1. **编排层（脚本）**：生成派发简报文件、登记任务状态、等待回执文件落盘、跑验收与归档；
2. **桌面执行通道（agent cu 单元）**：由主控在调度间隙通过 computer-use 能力唤起 / 聚焦 MiniMax Code、粘贴简报并发送；回执文件是完成判据，截图 / UI 状态仅作兜底。

崩溃恢复：进程 / 会话重置后，凭 taskId 从索引 + L2 状态 + 文件工件在新会话重建上下文，不依赖对话历史；`working` 且租约未过期的任务须编排者显式释放后才可接管。

## 10. 可视化网页

静态页面（无构建链、无后端服务），读取快照 JSON 渲染：

| 视图     | 内容                                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------------------------- |
| 概览     | 自治开关状态、各状态任务计数（ready / submitted / working / completed / failed / rejected / 死信）、循环起止时间 |
| 任务列表 | taskId、contextId、类型、状态、角色、返修次数、验收结论、交付记录指针                                            |
| 任务详情 | 工件指针、护栏明细、history、围栏标记、返修链                                                                    |
| 死信区   | 死信任务、失败证据、已尝试路径、建议决策点                                                                       |
| 交付包   | 最近一次夜间交付包汇总、遗留项与待批动作                                                                         |

**开关落盘方式**：静态页在 `file://` 下不能写本地文件；网页以只读展示为主；自治开关经 CLI（`pnpm orchestration:config --enable/--disable`）写回 `config.json`，网页刷新后读取最新快照。

## 11. 选型取舍

| 决策         | 选择                                                      | 理由                                                              |
| ------------ | --------------------------------------------------------- | ----------------------------------------------------------------- |
| 运行时依赖   | 仅 node 内置模块 + 本仓已有 `ajv`                         | 不新增第三方依赖；遵守 adapter 红线                               |
| L2 状态存储  | JSON 文件 + 原子写（临时文件 + 替换）；store 接口抽象隔离 | 当前规模足够；后续换 DB / 工作流引擎只换 store 实现，上层流程不变 |
| 网页形态     | 静态 HTML + 原生 JS + CSS                                 | 无需前端构建链；产物可直接浏览器打开                              |
| 语言模块格式 | ESM（`.mjs`）                                             | 与 `scripts/` 既有 node 脚本先例一致，无构建步骤                  |

## 13. 风险与限制

- 桌面夜间可靠性是最大现实风险：依赖桌面解锁、不休眠、执行代理已登录；兜底靠文件回执 + 租约 + 死信，不靠 GUI 状态；
- 当前为单代理单会话规模，未上 DB / 工作流引擎；若后续多会话共享状态或文件索引成瓶颈，再按 AF-005 触发判据迁移持久层；
- 脚本验收只覆盖机读可判定项；语义与口径判断仍由人工 / 验收角色承担；
- 自治模式默认关闭；冻结动作在夜间不自动执行，留待人工早上批准。

## 14. 交付物与闸门

**工具链**：`scripts/orchestration/` 六个模块 + `config.json`；**网页**：`web/orchestration/` 三件；**本备忘**：本文档。

闸门：

- 所有 `.mjs` 通过 `node --check` 语法检查；
- 框架仓新 schema（agent-card）样例通过 ajv 校验；
- 改动文件无 BOM、CR=0、纯 LF；
- 既有索引 JSON 双解析器通过；
- 分组提交：框架仓规范件独立提交；本仓工具链 / 网页 / 文档分组提交；push 由主控执行。
