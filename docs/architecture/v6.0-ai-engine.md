## 1. 模块概览

V6.0 后端在 `mofang-nestjs` 仓库新增 3 个模块 + 1 个 LLM 抽象层 + 3 个 cron:

| 模块 | 端点前缀 | 职责 | 反双胞胎边界 |
|---|---|---|---|
| **AIEngineModule** | `/ai/*` + `/v1/chat/*` | §3 用户画像 / 推荐 / 解锁 / 效果 / LLM 编排 / §11.2 危机 | 不写急救工具 / 不写 LLM 调用细节 |
| **EmergencyModule** | `/emergency/*` | §4.2 急救会话上报 + 跨设备同步 + 工具效果统计 | 不写急救工具本身 (端侧 SQLCipher) |
| **GameUnlockModule** | `/inner-world/game-unlock/*` | §6 Inner World 游戏化模块解锁进度 | 不写游戏逻辑 (端侧 Flare/Unity) |
| **LLM 抽象层** (`src/llm/`) | — | OpenAI 兼容协议多厂商可插拔 | 不写业务路由 / 不写推荐算法 |
| **3 个 cron** | — | 解锁评估 / 效果聚合 / crisis 清理 | 不写评估算法 / 不接新数据 |

## 4. 部署

### 4.1 最小化部署 (V2.0)

```bash
# 1. 安装依赖
pnpm install

# 2. 启动基础服务 (MySQL + Redis)
docker compose up -d mysql redis

# 3. 跑 migration
pnpm migration:run

# 4. 配置 .env (至少填 1 个 LLM_*_API_KEY)
cp .env.example .env
vim .env  # 配置 LLM_OPENAI_API_KEY 等

# 5. 启动 API
pnpm start:dev    # dev
# 或
pnpm build && pnpm start  # prod
```

### 4.2 完整部署 (V3.0 + RAG + LiteLLM)

```bash
# 1. 启动所有容器 (含 Qdrant + LiteLLM)
docker compose --profile rag --profile litellm up -d

# 2. 验证 Qdrant
curl http://localhost:6333/healthz
# {"status":"ok"}

# 3. 验证 LiteLLM
curl http://localhost:4000/health/liveliness
# {"status":"alive"}

# 4. 跑 smoke (12 步全链路)
pnpm smoke:ai
```

### 4.3 反向代理 (Nginx) — 关键配置

```nginx
# SSE 必须禁用缓冲 + 长连接
location /v1/chat/completions {
    proxy_pass http://api:3000;
    proxy_http_version 1.1;
    proxy_set_header Connection '';
    proxy_set_header Host $host;
    proxy_buffering off;        # 关键: SSE 不能缓冲
    proxy_cache off;
    proxy_read_timeout 600s;    # 关键: 长流连接 10 分钟
    chunked_transfer_encoding on;
}
```

## 5. 配置 (.env)

完整字段见 `.env.example`, 关键项:

| Key | 必填 | 默认 | 说明 |
|---|---|---|---|
| `LLM_<PROVIDER>_API_KEY` | 是 (至少 1 个) | — | provider API key |
| `LLM_<PROVIDER>_BASE_URL` | 否 | 厂商默认 | OpenAI 兼容地址 |
| `LLM_TIER_<TIER>_PROVIDER` | 否 | openai | tier 路由 |
| `QDRANT_URL` | 否 | `http://localhost:6333` | 向量库地址 |
| `QDRANT_API_KEY` | 否 | — | Qdrant 1.x 鉴权 |
| `RAG_TOP_K` | 否 | 5 | 检索 top K |
| `RAG_SCORE_THRESHOLD` | 否 | 0.7 | 分数阈值 |
| `CRISIS_*_KEYWORDS` | 否 | 内置 | 危机关键词 (V2 静态, V3 接 LLM) |
| `CRISIS_HIGH_RESOURCE` | 否 | 全国热线 | high 级别推送资源 |

**优先级**: DB override > .env > 默认 (V3 接 ai_provider_configs 表)

## 7. 监控 + 告警

### 7.1 Prometheus metrics (V3 接)

| metric | type | 用途 |
|---|---|---|
| `ai_chat_completions_total` | counter | chat 调用次数 (按 provider/tier 维度) |
| `ai_chat_completion_duration_seconds` | histogram | chat 响应时间 |
| `ai_chat_tokens_total` | counter | token 消耗 (prompt/completion) |
| `ai_crisis_events_total` | counter | 危机事件数 (按 level) |
| `ai_rag_search_duration_seconds` | histogram | RAG 检索延迟 |
| `ai_qdrant_connection_state` | gauge | Qdrant 连接状态 (1=up, 0=down) |

### 7.2 告警规则 (V3 接)

```yaml
# alerts.yml (Prometheus)
- alert: QdrantUnreachable
  expr: ai_qdrant_connection_state == 0
  for: 5m
  annotations:
    summary: "Qdrant 不可达 — RAG 软降级"
    description: "RAG 检索返回空 context, LLM 退化为无上下文回答"

- alert: CrisisEventSpike
  expr: rate(ai_crisis_events_total{level="high"}[1h]) > 5
  for: 0m
  annotations:
    summary: "HIGH 危机事件激增"
    description: "1h 内 >5 条 high — 人工介入"

- alert: LLMTokenBudgetExhausted
  expr: increase(ai_chat_tokens_total[1h]) > 1000000
  for: 0m
  annotations:
    summary: "LLM token 消耗超预算"
    description: "1h 消耗 1M tokens — 检查用户行为 / rate limit"
```

## 9. 故障排查

| 现象 | 排查 |
|---|---|
| `/v1/chat/completions` 503 | `.env` 没配 `LLM_<PROVIDER>_API_KEY`, 至少配 1 个 |
| Qdrant 警告 `unreachable` | docker compose `up -d qdrant`, 检查 `QDRANT_URL` |
| `Cannot resolve ChatProvider` | `npm install @langchain/openai` + 跑 build |
| SSE 流断 | Nginx `proxy_buffering off` + `proxy_read_timeout 600s` |
| CrisisEvent INSERT 失败 | 检查 FK 是否指对 user 表 (uid 类型 VARCHAR(36) vs BIGINT) |
| emergency_sessions upsert 失败 | id 必须是前端 UUID VARCHAR(36), 不是 INT 自增 |
| Migration `No migrations are pending` | 检查 `bin/ormconfig.ts` 是否 import 新 migration |
