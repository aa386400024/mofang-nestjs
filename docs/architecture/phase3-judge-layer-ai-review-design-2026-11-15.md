> 日期：2026-11-15

> 基线 HEAD：`bedd702`（TD-18 已交付推送）
> 事实源：`src/auto-practice/metrics/`（指标字典 / 快照 schema / 回归判定器 / 分档判据）、`src/engine-adapters/eval/`（WP-E 离线评测流水线）、`src/engine-adapters/cognition/`（D-1/D-7 事件分类器）、`src/llm/`（provider 路由链）、`src/shared/infra/observability/pii-redactor.ts`（现有脱敏模块）、WP-A / WP-E 交付记录

## 1. 定位与边界

### 1.1 要解决的问题

Phase2.5 已具备离线规则评测（WP-E）与批次指标回归设施（WP-K），但**长会话整体质量、效度初评、场次级专家视角评审**目前没有自动化抓手。内部阶段找不到真实专家，手工评审无法成批覆盖。目标是把评审链路先用 AI 自动化打通：

```
批次跑批 → L0 规则指标 + L1 事件分类 → L2 LLM judge 场次级评审 → 评审单 + 证据片段 → 回归护栏 / 人工复核队列
```

### 1.2 边界声明（不可模糊）

- Judge Layer 产出的是**机器代理评审**，用于工程回归、问题发现与评审单草稿；**不是临床效度证据**，不构成对咨询师执业能力的认定。
- L2 judge **不替代**真人专家；L3 真人评审接口预留，空队列运行，待专家资源到位后补录并做 AI / 真人一致性校准。
- 危机 / 自伤判定**永远走本地规则**，judge 不参与危机结论（沿用 WP-A 红线）。
- 内部阶段语料为 AI 虚构角色对练脚本；脱敏层按"将来会接入真实用户演练输入"的标准预留，不因当前是虚构脚本而省略。

### 2.2 现有缺口（本方案要补的）

1. **无 LLM judge**：场次级对话质量只有规则指标与事件分类，没有综合评审视角。
2. **无 rubric 版本化**：评审维度、分档锚点、prompt 文本没有版本号与血缘落库。
3. **无人工复核队列**：低一致率 / 低信心场次没有入口汇入真人评审。
4. **无 AI / 真人一致性校准**：缺真人评分样本与一致性矩阵，无法回答"机器评审和专家差多少"。
5. **judge 信号未进回归判定**：现有 evaluator 只消费规则指标，judge 维度信号尚未纳入 verdict。

### 2.3 现有脱敏能力的两处缺口（judge 场景必须正视）

- **遮不掉语义敏感信息**：人名、地名、家庭关系、创伤细节、自伤表述，正则识别不了。
- **字段整体遮蔽会毁掉待评内容**：judge 必须读到对话才能打分，日志那套"命中字段名即 `[REDACTED]`"的口径不能直接用于 judge 输入。

⇒ judge 需要单独一层脱敏设计（§5），不能复用日志 redactor 直接顶上。

## 3. 四层评审模型

| 层     | 名称         | 现状     | 输入                                          | 输出                                                | 边界                                             |
| ------ | ------------ | -------- | --------------------------------------------- | --------------------------------------------------- | ------------------------------------------------ |
| **L0** | 规则轨迹指标 | 现有     | 场次轨迹 + 指标字典                           | 各 `dim.* / event.* / strategy.*` 数值（nullable）  | 纯计算、零模型调用；口径单一真相源在指标字典     |
| **L1** | 事件分类器   | 现有     | 轮次文本 + 状态                               | 事件类别 / 标签 / 分类模式                          | 三态演进；输出作为 L2 的上下文特征，不做综合评审 |
| **L2** | LLM-as-judge | **新增** | L0 指标值 + L1 事件标签 + 脱敏片段（见 §5.2） | 三维度分档 + 引用片段 + 理由 + 结构化 JSON + 信心度 | 场次级调用；不碰危机结论；影子阶段只旁路观测     |
| **L3** | 真人评审     | 接口预留 | L2 评审单 + 原始 / 脱敏轨迹                   | 真人分档 + 批注                                     | 空队列运行；AI / 真人一致性校准在 P3 补录后做    |

分层原则：L0/L1 输出是 L2 的**事实上下文**，L2 不在没有规则佐证的情况下凭空定性；L3 是最终仲裁口径，L2 结论始终标注机器代理属性。

## 4. L2 judge 设计

### 4.1 Rubric 三维度

评审维度沿用现有指标字典的三维归属，避免双口径：

| 维度组       | 评审子项                                 | 主要佐证（L0/L1）                                                                    |
| ------------ | ---------------------------------------- | ------------------------------------------------------------------------------------ |
| **来访侧**   | 人设一致、情绪真实、阻抗表现、连贯不复读 | `dim.bond/valence/arousal/verbal`、`event.*`、`text.disfluency.*`、复读 / 近重复检测 |
| **咨询师侧** | 同盟推进、克制度、在场感、危机回应       | `dim.trust/safety/bond` 轨迹、策略 `strategy.*`、危机事件标签                        |
| **结构侧**   | 探索深度、节奏、会话闭环、表达流利度     | `dim.depth/style`、`exploration.rate` / `character_coverage`、`text.disfluency.*`    |

每维度输出：**分档锚点（草案 1–5 或 0/1/2，待 §9 决策）+ 引用片段（轮号 + 脱敏文本）+ 理由 + 信心度**。结构化 JSON 走既有 `llm-json.client.ts` 唯一链，不另起结构化输出通道。

> rubric 文本、分档锚点、prompt 模板在实现单里落成版本化配置；本备忘不锁定具体档位文案。

### 4.2 Judge 端口与 provider 选型

- **端口抽象**：参照仓内仓储端口 / 分类器端口先例，judge 抽成接口（如 `ReviewJudgePort`），provider 是实现；业务层只依赖端口，切换厂商不改动评审逻辑。
- **独立 providerId**：judge 的模型配置与对话生成的默认 provider **解耦**，显式配置独立的 `judgeProviderId` / `judgeModel`。
- **跨模型族错开**：judge 模型族与被评角色（AI 来访者）生成模型族刻意错开，避免同源模型互背书；角色线将来换厂商，judge 跟随错开。
- **复用现有链**：走 `llm-router` 与既有 provider 适配（DeepSeek / Doubao / Qwen / MiniMax），**不新增第三方依赖**。
- **厂商压测**：具体选哪家，待第二家 key（Doubao）到位后，用一批固定样本压双 judge 一致率再定；选型沿用"同档费用取最佳模型"口径。

### 4.3 三态演进（沿用 D-1/D-7 思路）

1. **shadow**：judge 旁路跑，结果落库但**不进** verdict、不阻断任何批次；用于观测分布、抽核对齐、积累样本。
2. **双 judge 一致率达标**：两个不同族 judge 的分档一致率达到 §9 门槛后，judge 信号方可作为候选进判据表。
3. **进判据表**：经基线回放校准后，judge 维度信号纳入回归判定；中性方向维度不参与好坏判定的纪律沿用现有 evaluator。

### 4.4 版本血缘

- 每场评审单落库：judge providerId、模型名、prompt 版本、rubric 版本、输入快照指纹。
- rubric / prompt / judge 模型任一变更，进入配置指纹；指纹不同的批次之间，judge 维度分数**自动 incomparable**，不做直接好坏对比（沿用现有 fingerprint 不可比口径）。

### 4.5 数据产物与 schema 演进

- **场次级评审单**：三维度分档 + 理由 + 信心度 + 轮级证据片段引用。
- **轮级证据片段**：由 L0/L1 规则产出定位，L2 引用；不要求 judge 逐轮打分。
- **人工复核队列**：表结构预留真人分档 / 批注字段；初始空队列；入队规则 = 双 judge 低一致率 / judge 低信心度 / 危机相邻轮次抽检。
- **AI / 真人一致性矩阵**：P3 真人补录后产出，按维度汇总一致率与分歧分布。
- **快照 schema**：现有 `BatchMetricsV1` 字段只增不删；judge 段作为**新增可选段**接入（schema 升 v2 或可选字段，实现单定）；指标字典新增 `judge.*` 段，键进 metrics 映射。

## 5. 隐私与脱敏

### 5.1 既有红线（不可违背）

- WP-E：评测全程离线计算，不调外部 LLM 做裁判，心理数据不出境。
- WP-A：审议不传对话原文，只传结构化事件分类 + 状态对比 + 角色简述；高风险轮次永远本地规则。
- 日志 / Sentry：心理对话原文、量表答案、画像、自伤输入禁止进普通日志 / crash report / 网络日志；文档只出码与计数。

> 本方案引入 L2 外部 judge，是对 WP-E"不调外部裁判"口径的**显式例外**；该例外的适用范围、脱敏前置与红线护栏在本节锁定，需在实现单与交付记录里显式登记，不默认延续既有离线口径。

### 5.2 定案路径：外部国内厂商 judge + 专用脱敏层

**私有部署路径已排除**：内部阶段成本不允许私有化模型。主路径定为现有国内厂商 provider（DeepSeek / Doubao / Qwen / MiniMax；排除出境红线厂商），经专用脱敏层后送审。

**judge 专用脱敏层（新增，独立于日志 redactor）**：

| 能力         | 来源                | 说明                                                                             |
| ------------ | ------------------- | -------------------------------------------------------------------------------- |
| PII 正则遮蔽 | 复用 `pii-redactor` | 手机号 / 身份证 / 邮箱 / 凭据 / IP 截断，口径与日志一致                          |
| 语义去标识   | **新增**            | 人名 → 角色代号；地名 / 单位 / 家庭关系 → 泛化类别；不保留可定位到具体真人的线索 |
| 敏感细节降级 | **新增**            | 自伤 / 创伤细节降级为类别标签（如 `self_harm: ideation`），不送原文描述          |
| 输入组装     | **新增**            | 优先送"事件标签 + 维度轨迹数值 + 泛化片段"；整稿仅必要场次送；控制单场 token 量  |

### 5.3 不可放宽的红线（外部路径下收紧）

1. **危机 / 自伤轮次不送外部 judge**，永远本地规则判定；队列与评审单里该类轮次只引用规则结论。
2. **PII 必须先过正则脱敏**，未过脱敏的输入不得进入 judge 客户端调用。
3. **库内同时留原始文本与脱敏文本**；外部 judge 只见脱敏版；原始档仅本地评审 / 真人复核可访问。
4. **供应商条款**：确认所选厂商不留存对话、不用于模型训练；条款不可证实时该厂商不得作为 judge。
5. **结论标注**：所有 judge 输出与报告显式标注"机器代理评审，非临床效度证据"。
6. 脱敏口径进配置指纹、版本化；脱敏规则变更视同 rubric 变更，触发跨批判分不可比。

### 5.4 成本护栏

| 杠杆     | 口径                                                                                    |
| -------- | --------------------------------------------------------------------------------------- |
| 调用粒度 | judge 只跑场次级；轮级证据由 L0/L1 规则产出，LLM 不逐轮打分                             |
| 输入大小 | 结构化特征 + 泛化片段优先；整稿按需；复用现有截断口径                                   |
| 影子阶段 | 小批抽样送审，不全量；一致率达标前结果只旁路观测                                        |
| 选型     | 同档费用取最佳模型；复用现有 router / provider，不新增依赖                              |
| 失败兜底 | judge 调用失败 / 超时不阻断批次跑批；该场 judge 段记 null，覆盖率口径沿用现有 skip 机制 |

## 7. Phase3 分阶段路线

### P0 · Rubric + Judge 骨架 + Shadow 落库

- rubric 配置版本化（维度 / 锚点 / prompt 模板 + 版本号）；
- `ReviewJudgePort` 端口 + 首个 provider 实现 + 脱敏层骨架；
- judge 影子模式接入批次跑批，评审单与血缘落库；**不进 verdict**；
- 快照 schema / 指标字典扩 `judge.*` 段；单测覆盖端口替身、脱敏纯函数、schema 守卫。
- **出口**：固定样本可旁路产出结构化评审单；血缘字段齐全；无 judge 信号进入回归判定。

### P1 · 双 Judge 一致率 + 人工复核队列接口

- 第二模型族 judge 接入；双 judge 分档一致率统计；
- 人工复核队列表 + 入队规则（低一致率 / 低信心 / 危机相邻抽检）；真人字段预留；
- AI / 真人一致性矩阵框架（真人样本为空时矩阵留空结构）。
- **出口**：一致率报表可出；队列可查询 / 入队；真人补录路径打通。

### P2 · Judge 信号进回归判据 + 基线回放

- 双 judge 一致率达标后，judge 维度信号经阈值纳入 evaluator；
- 基线批次回放校准，确认 judge 信号不引入误报回归；
- 判据表与指纹不可比口径对齐。
- **出口**：judge 信号参与 verdict 且经基线回放验证；误报 / 漏报有批次证据。

### P3 · 真人补录校准 + Rubric 迭代

- 真人评审样本补录；产出 AI / 真人一致性矩阵；
- 按分歧分布修订 rubric 锚点与权重；版本血缘记录每次校准；
- 效度研究另立临床研究单，不在 Judge Layer 工程单内下效度结论。

## 8. 风险与边界

| 风险             | 说明                                         | 护栏                                                            |
| ---------------- | -------------------------------------------- | --------------------------------------------------------------- |
| 同源偏置         | judge 与被评角色同模型族，互相背书           | 跨模型族错开；双 judge 异族对照；模型组合进血缘                 |
